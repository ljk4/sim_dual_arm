##### filter 必须先在容器路径下冻结

DSH-040 候选 filter 记录的是宿主绝对路径（`/home/ljk/...`），而

`training.model_ready` 前失败。

只是把源路径记录为 `/learning-data`、`/source-data`、`/workspace`），再冻结其
SHA256。下面命令不训练，只调用现有 `filter-anchors`；使用 `formal-select.container.json`
是因为它已把 attempt 路径映射到 `/source-data/attempts/...`：

```bash

  -v "$LEARNING_SOURCE":/opt/lerobot:ro \

  -v "$WEIGHTS":/learning-cache:ro \
  -v "$OUTPUT_ROOT":/output:rw \
  sim-dual-arm/learning:act-dev \

    --config /workspace/configs/learning/act_sample_filter.yaml \

    --output "/output/experiments/act-static-b16-20k-20261103/training-filter.json"
```

生成后立即记录并冻结：

```bash

"$PROJECT_PYTHON" - "$FILTER" <<'PY'
```

#### 6. 64 步真实预检（不是 20K 模型）

用同一 YAML 派生预检配置，只改三项：`full.reserve_seconds: 300.0`，

```bash

"$PROJECT_PYTHON" - "$CONFIG" "$EXPERIMENT_ROOT/preflight/preflight.yaml" <<'PY'

doc["modes"]["full"]["reserve_seconds"] = 300.0

```

把 `TRAIN_CONFIG` 指向这个 preflight YAML，然后用 Compose 的一次性覆盖命令跑

```bash
  -f deploy/compose/act_training.yaml run --rm train \

  --config /training-config.yaml --max-steps 64
```

必须检查：

- `training_report.json`：`steps=64`、`planned_steps=64`、`reason=completed`，
  `sample_filter.source_frames/eligible_frames/excluded_frames` 与冻结 filter
  一致；
- `metrics.jsonl`：loss/grad finite，至少一条 validation 行且
  `val_frames=2160`；
- `events-<segment>/` 的 `training.model_ready`：`resumed=false`、
  `train_source_frames`/`train_eligible_frames` 正确、`validation_frames=2160`、
  `sample_filter_digest` 与 filter 一致；
- `latest.pt` 的 `training_binding.sample_filter_sha256` 等于 `sha256sum "$FILTER"`；
- 估算 20K **墙钟**时不要用 `step_seconds`：该字段只覆盖
  `_process_sample` 之后的 forward/backward，漏掉图像读取、解码和预处理。用
  两条不跨验证边界的稳态 train 记录（例如 step 20 与 step 60）：

  ```text
  steady = (elapsed_seconds_60 - elapsed_seconds_20) / (60 - 20)
  ```

  这个差值才包含数据读取/解码/预处理和计算。再从 `events-<segment>/` 或
  `docker compose logs -t` 的事件时间戳测一次完整验证和一次保存的墙钟
  `validation_wall`、`save_wall`，按
  `20K ≈ 20000 * steady + 20 * (validation_wall + save_wall) + final_save_wall
  + startup_wall` 估算；`startup_wall` 用首条 train 记录的 `elapsed_seconds`
  减去其 `step_seconds` 近似，包含数据集 hash 校验和首次取数。把这个估算与
  预检后的剩余预算比较，并为验证/保存抖动留余量。

- 同时记录 `peak_vram_allocated_mb` 和 `peak_vram_reserved_mb`。若估算超过
  剩余预算，直接报告，不要延长预算或把 20K 说成已完成。

64 步产物只是预检，**不得**称为 20K 模型、不得导出 bundle、不得替换旧模型。
旧 5K checkpoint 仍可按原格式读取，但新配置带 filter、batch16 且路径不同，
