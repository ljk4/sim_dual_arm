# DSH-055：仿真 Docker 职责与操作流程简化

## 目标与执行决定（2026-11-04）

用户批准修正 simulation Docker 审查问题。保留每实现一 Dockerfile、一 Compose、
一 run.sh。只改变依赖环境、入口、挂载、版本核验和相关文档/测试；保留全部物理、
控制、接口、模型语义和数值参数，不训练、不执行新的完整任务 rollout。

1. Ruckig builder 只安装现有编译工具锁，不再安装通用 requirements-dev。
   仿真最终环境只含实际使用的 ROS/MuJoCo/渲染/校验依赖；移除 gRPC/protobuf、
   rosbag/MCAP 和重复 Pillow 安装。日常 pytest/ruff 单独列测试依赖；colcon 保留，
   用于本端显式 build-ros-sdk，Git 用于现有固定资产 fetch。无新镜像变体、无大段
   Dockerfile 内嵌脚本；Ruckig 必要的内部构建 stage 与来源校验保留。
2. 仿真 Compose 仅保留 /workspace:ro、/data:rw、/build:rw、/opt/ros-dev:ro 四个
   挂载。资产放 /data/simulation/assets/mujoco_menagerie；资产 summary 放
   /build/assets/panda.json。不再挂载整个 third_party 或旧双路径别名。主助手在实际
   验收前将原资产 checkout 移到新的宿主对应目录并核对内容，DSH 不操作主数据。
3. Fast DDS 配置仅从源码挂载读取；稳定的 Python/ROS/EGL 默认放 Dockerfile，
   Compose 只保留所需角色声明、路径与宿主 GPU/网络/UID 绑定，不重复覆盖相同值。
   run.sh 去掉 SIM_BACKEND_CONFIG/SIM_SCENE_CONFIG 等不透明环境覆盖；backend
   由调用方显式 --config，数值仍由现有 YAML 控制。场景/运动学检查允许已有明确
   YAML 默认和 CLI 覆盖，不新增万能配置系统或动态插件。
4. 宿主 scripts/env.sh 的 exec 改成原始命令透传：source 公共 setup 后 exec "$@"；
   shell 进入已有容器并 source 同一 helper。不再通过 PROJECT_ENTRYPOINT 分发业务，
   删除三个 Compose 中该冗余字段。业务统一在容器内调用各端 run.sh；不保留旧
   宿主功能名兼容别名。build 仅构建依赖镜像，SDK 生成由显式容器命令执行，删除
   自动 SDK 和 SKIP_SDK 路线。runtime/learning 核心和 Dockerfile 不改，仅同步受影响
   文档、Compose 字段、宿主入口与检查器/测试。
5. simulation run.sh 提供 build-ros-sdk，调用现有公共构建工具；backend 保留 SDK
   完整性/来源检查，test 不再无条件检查 SDK。run.sh 保持直接、可读的 case 分发，
   无需保留 simulation 的 shell/exec 功能包装；默认 idle 仍不启动任务。
6. sim-requirements.lock 作为唯一手工版本来源。移除手工 sim-packages.json 和探针
   的版本数字字典；image_metadata 从锁生成 /opt/sim/versions.json，记录预期版本、
   实际版本和锁文件摘要，并在构建时拒绝不匹配。探针使用生成报告核验实际版本，
   并检查挂载锁与镜像绑定，保留来源检查和故障原因，不用另一处手工数字冒充核验。
7. simulation Compose 启用 init:true；说明先结束后台业务再停止环境。主助手实际
   验证 backend SIGINT 收尾与 idle 容器停止，无新增任务 episode。

### 候选改动

- 仿真依赖：删除 `sim-packages.json`；Ruckig builder 只使用编译工具 lock。最终
  stage 使用系统 jsonschema/yaml/colcon、`sim-requirements.lock` 的 hash 包和独立的
  `sim-tools-requirements.txt`（pytest 8.3.5、ruff 0.11.13、SDK 构建所需
  setuptools/wheel）；移除公共 requirements-dev、rosbag/MCAP、gRPC/protobuf 和重复
  Pillow。保留 Ruckig 0.15.3 及原编译/运行 lock 内容。
- 仿真 Compose/Dockerfile：只挂载 `/workspace:ro`、`/data:rw`、`/build:rw`、
  `/opt/ros-dev:ro`，启用 `init: true`；Dockerfile ENV 固定 Python/ROS/EGL/路径默认，
  Compose 保留角色、宿主绑定和 NVIDIA 设置；Fast DDS 只从
  `/workspace/infrastructure/docker/fastdds.xml` 读取，不再 COPY。资产默认改为
  `/data/simulation/assets/mujoco_menagerie`，摘要 `/build/assets/panda.json`。
- 入口：`scripts/env.sh` 的 `build` 只构建镜像，删除自动 SDK 与 `SKIP_SDK`；
  `shell`/`exec` 进入已有容器并 source 同一 `setup.sh` 后执行原始 argv。
  simulation `run.sh` 增加显式 `build-ros-sdk`，backend 必须由调用方给 `--config`，
  test 不检查 SDK，删除 shell/exec 包装和 `SIM_*_CONFIG` 隐藏覆盖；三个 Compose
  删除 `PROJECT_ENTRYPOINT`。
- 版本核验：`image_metadata.py sim --requirements` 从唯一 lock 生成预期/实际版本与
  lock 摘要，构建时版本不符即失败；probe、scene、kinematics 读取
  `/opt/sim/versions.json`，并对比当前挂载 lock 摘要。保留版本不符、源路径 shadow、
  锁更新但镜像过期的失败原因。
- 同步精简当前 README/目录说明及共享入口提示；历史正文未改写。
