# DSH-043：源码挂载优先与 Docker 构建逻辑整理

状态：已验收并整合，2026-11-03。DSH 预检期间 API 中断，主助手接管实现与验收。

## 目标与决策

用户要求源码挂载为主，必要时才 COPY，避免修改后仍运行镜像旧代码；Dockerfile
绝对禁止成段程序代码。本阶段改变部署/构建方式，不改变控制、学习或任务算法。

- 现有运行 target 名称保留，mock/runtime/test/policy 改为源码挂载依赖镜像，
  项目源码、配置、profile 和测试不再 COPY 入镜像。没有实际发布需求，不额外
  创建一套复制源码的 release 分支。
- 允许 COPY 固定依赖清单、必要的最小环境 bootstrap、镜像来源信息和构建产物；
  Ruckig wheel 从 builder 复制到运行层属于必要产物复制。
- Dockerfile 只保留声明、安装和调用独立脚本。禁止 heredoc 程序、嵌入多行
  Python/Shell 和通过 echo/base64 等方式隐藏脚本；多行 apt/pip 参数允许。
- 将 backend-sim 中版本采集、Ruckig 构建来源记录和安装校验移到 `tools/build/`。
  推荐一个职责明确的元数据工具、三个具名子命令，参数为输入/输出路径；使用
  BuildKit 只读 bind mount 调用构建工具，不复制业务代码。
- 保持源码在 PYTHONPATH 前位；缺少源码或 SDK 挂载时明确失败。Policy SDK 必须
  核对当前 proto 摘要和实际模块来源，不能使用镜像内旧 SDK 回退。
- 修改 Python/配置后需重启对应进程；不承诺运行中自动热重载。IDL/proto 改动
  需重新生成 SDK，过期检查应给出重建入口。

不改历史 000～042、功能与实践目录，不把本阶段自动收录到重要实践库。

## 实现计划

1. 提取 backend-sim 三段 Python，输出 schema、字段、版本和 wheel SHA 语义不变；
   单独可读、可调用，不做泛化插件框架。错误明确且非零退出。
2. backend-sim 的 mock target 继承现有 dev ROS 依赖层，runtime/test 同样使用
   dev ROS 层与挂载入口；移除业务 COPY、镜像内业务安装及旧源码回退路径。
   保留依赖安装、target 名称和默认命令的用途。不要复制 dev_ros.sh 的职责。
3. learning protocol/policy 不再 COPY 业务或内置项目 SDK；通过挂载使用 Policy SDK。
   添加小型 SDK 校验工具与薄入口，校验 source.sha256 等于当前 proto SHA，
   并确认导入的 policy_pb2/policy_pb2_grpc 实际来自挂载 SDK 根。
   SDK 缺失、摘要过期或导入回退一律失败。ACT 各 target 的环境/依赖保持兼容。
4. 增加 `tools/build/policy_sdk.sh` 之类的明确宿主入口，通过依赖容器将唯一 proto
   生成到显式的宿主 `.build/generated/policy-sdk`，源码 RO、输出 RW、按调用者
   UID/GID运行。镜像/输出可覆盖以便隔离验收。不依赖宿主安装 grpc_tools。
   避免覆盖无归属的非空输出；当前摘要/模块都有效时可复用，过期时只重建明确
   属于生成器的路径。不得把 SDK 或源码 COPY 进镜像作为替代。
5. stage2.sh 默认改为构建 ROS base、dev 依赖、生成挂载 ROS/Policy SDK 和必要的
   Policy 依赖镜像，与当前 mock_collect 的实际 Compose 路径一致。复用 dev.sh。
   Docker 可通过 DEV_DOCKER 指定，镜像、ROS 输出与 Policy 输出可覆盖；不强改
   其他公共启动器默认值。不自动删除现有镜像/容器/网络。
6. 保留简短的 source/exec 容器入口，源码验证、SDK 检查和元数据逻辑归工具；
   清理 Dockerfile 的内嵌 python -c 检查，改调用独立具名脚本。更新相关目录说明。
7. 针对真正的失败边界自测：SDK缺失/过期/导入回退、元数据校验和 Dockerfile
   禁止嵌入程序/复制业务源码的约束。测试不依赖 GPU、网络或实际 Docker。
   不为每行 Dockerfile 写镜像式断言；重点防止旧代码回退和规则倒退。

## 独立验收计划

- 审查全部 Dockerfile，所有业务源码/config/profile/test均通过挂载提供，
  无嵌入程序块，必要 COPY 逐项说明用途。
- 针对性 pytest、Ruff、shell 语法、Compose config 与 Docker build --check。
- 以候选源码、新标签构建相关依赖 target，不重新打标当前训练镜像。
- 实际容器验证挂载缺失/SDK过期拒绝，正确挂载时模块来自宿主源码；同一镜像下
  改隔离源副本、重启进程后观察到新值，且无需重建镜像。
- 新 ROS 构建目录与独立 Policy SDK，用公共入口跑一次 CPU mock 自动采集，
  核对退出/日志/独立 MCAP 审计和所属资源清理。
- 保留原失败与未测项。元数据 helper 需实际运行验证，但不为本次纯部署重构
  启动 GPU/完整堆叠或消耗任务随机种子。
