# DSH-048：融合推理窗口对照与首次成功验收

## 目标与决策

延续用户“至少真实成功一次”的当前任务，不追加训练、不放宽原限位/跟踪/成功判定。DSH-045/046/047 已修复明显停滞、准备竞态及预测跳变；首批4次均保留失败，已封存。

已有30403的9条真实admitted预测，在固定原anchor下离线比较系数0～1、5/10/15/20点窗口：20点在第9条夹爪偏差2.8466cm超原2cm，10点全部通过；15点在正系数下也通过，但余量较少。先用0.5秒（10点）+系数0.01的新窗口试验。不向模型输入物体真值，不用示教/回放或脚本接管。

本阶段复用已实现的程序，仅生成隔离试验配置、执行与独立验收，由主助手运行，不再调用DSH写重复代码。源码默认20点配方和旧模型包保留。首个新批次最多4次，种子30500～30503，逐次根据证据决策；所有campaign合计仍低于30GiB且保留磁盘/记录余量，失败计入。不从旧台账重用种子或清空历史。

准备中。原始报告位于 `.build/reports/dsh-048/`；隔离配置位于 `.build/generated/act-window-048/`，新追加式台账位于 `var/campaigns/panda_stack_act20k_temporal_windows_20261103/`。

固定修复后首例30600：29次ACT预测后出现TRACKING_TIMEOUT，随后STREAM_ANCHOR_UNAVAILABLE仅是运动已停止的后果。MCAP表明唯一超差是已夹住4cm物块的右夹爪；双指约1N、低速、同一source，contact_ok=true。参考v只有+5.339e-14m/s，严格非正判定与卸载已有1e-9数值容差不一致，交DSH-051最小修复，不加大实测跟踪阈值。该失败保留，不继续盲跑同一数值缺陷。

30601：接触数值修复后59次真实预测、任务约29.69s，未再出现原误停；最终抓取/堆叠未成功，TASK_TIMEOUT。源码/模型配置相同但场景种子不同，不能把跨种子结果当严格修复对照。

因此新增一个最多1次的**同种子修复回归**：30600，隔离台账 `panda_stack_act20k_contact_regression_20261103`，对应原失败evaluation:30600:run-1793710201614369937，只验证夹持后数值误停修复。不是新独立评估，不计泛化成功率；原失败不删除、不改分母。此前任务书的“不能重跑”指同台账补跑/抹去失败；本次显式成对回归保留两次完整身份，服务当前用户至少一次真实成功和反例修复验证的目标。
