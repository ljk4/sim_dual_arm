# DSH-053：环境与业务执行分离

## 目标

承接 052，Dockerfile 只装环境，Compose 只启动空闲环境。所有采集、推理、训练、审计、导出、检查和 SDK 生成均通过容器内具名脚本执行。宿主仅保留环境构建、up/down、shell/exec 的薄入口，不运行项目 Python，不在 Compose 的 command/healthcheck 中嵌入业务。

## 实现要求

- 仿真、运行、学习三个环境独立，源码只读挂载，产物/构建目录显式可写挂载；环境启动不会加载模型、开始采集/训练或占用 GPU 计算资源。
- 每个端按职责提供容器内脚本，参数从配置读取，参数透传显式，不用一段 shell 拼接大程序。容器入口只准备 PATH/PYTHONPATH/ROS 等环境；功能脚本检查容器执行边界，支持 --help。
- 仿真通过 Robot API、学习通过 Policy API 与 runtime 通信，不新增运行端对具体物理引擎或模型内部的依赖。已有 CLI/核心实现复用，不复制控制/模型逻辑。
- 保留种子/预算、模型契约、ACK、接续、原始/准入/融合/参考/实测证据、物理成功和质量口径。准备配置不计为运行成功；退出码不代替物理判定。
- 旧宿主 Docker 启动器和只验证这些启动器的测试清理；长期协议、数据、轨迹、接触、浮点和故障回归保留。清理清单记录于本阶段，旧源码可从备份及阶段提交恢复。
- README 给出从环境准备到进入容器的实际命令，以及采集、训练、推理、审计入口。规范更新目录、容器执行边界和替换后端的方法，历史事实不重写。

## 验收

检查所有实际 Dockerfile 与 Compose、shell 语法、Python 导入、配置路径、核心长期回归。使用已安装镜像与新挂载入口进行真实容器 smoke，包括三路相机仿真步进、模型/数据入口与 ROS SDK；不追加训练、不自动复跑旧 campaign。明确记录未执行的检查。

### 实际实现

- 宿主唯一入口 `scripts/env.sh`：只接受 `build/up/down/shell/exec/config`，先检查
  `simulation/runtime/learning/all`，其余 argv 原样转给 Docker/Compose；不使用
  `eval`，不 source `.env` 为 shell，不运行项目 Python。它导出绝对
  `PROJECT_ROOT`/`BUILD_ROOT`/`DATA_ROOT`/SDK/资产/venv 变量；Compose bind source
  不再使用 `.`、`var`、`.build` 相对默认，缺根时明确提示走 env.sh。`build` 构建
  三端镜像；`build all`/`build runtime` 再通过 runtime 容器内的
  `build_ros_sdk.sh`、`build_policy_sdk.sh` 生成 SDK。
- 根 `compose.yaml` 用 `include` 组合三端：`simulation/mujoco/docker/compose.yaml`、
  `runtime/ros2/docker/compose.yaml`、`learning/lerobot/docker/compose.yaml`。服务名
  固定为 `simulation`、`runtime`、`learning`，全部为 `sleep infinity`，无
  `healthcheck`、无 Docker socket。simulation/runtime 共享显式 ROS 网络与域；
  runtime 另加入 learning 网络以解析 Policy endpoint；learning 不挂 ROS SDK、
  不设置 ROS 变量。网络名由 `PROJECT_NAME` 派生，不同项目不复用固定网络。
  simulation 使用 `runtime: nvidia` + `gpus: all` 保证真实 NVIDIA EGL；learning
  训练同样显式 NVIDIA；runtime 不申请 GPU/NVIDIA。
- 挂载边界：workspace `/workspace:ro`，并显式把 `BUILD_ROOT`/`DATA_ROOT` 再挂到
  `/workspace/.build`、`/workspace/var` 可写，使现行项目相对输出可用；同时保留
  `/build`、`/data` 可写。ROS SDK `/opt/ros-dev:ro`，Policy SDK
  `/opt/policy-sdk:ro`；LeRobot 源和权重缓存只读。仿真把 `third_party` 只读挂载、
  仅 `third_party/src` 子目录可写用于资产 fetch；资产 summary 用目录挂载，不用缺
  文件 bind 自动造目录。宿主学习 venv 仅作为可选只读挂载，默认镜像从锁构建。
- 公共入口 `setup.sh` 是唯一可 source 的环境准备，只设置 PATH/PYTHONPATH/ROS；
  `environment.sh` 只 source 后再 exec。`exec.sh` 解决 `docker compose exec` 不经过
  entrypoint 的问题，使 exec 中的 run.sh 也拿到 ROS/PYTHONPATH 和学习 venv；
  runtime 的 PYTHONPATH 明确包含 `/opt/policy-sdk`。`require-container.sh` 让业务
  脚本在宿主执行时明确退出 2。各端容器入口：
  - `simulation/mujoco/scripts/run.sh`：`backend`、`environment`、`scene`、
    `kinematics`、`assets`、`prepare`。
  - `runtime/ros2/scripts/run.sh`：`prepare`、`collect`、`policy`、`control`、
    `audit`、`export`、`campaign`、`evaluate`、`test`。
  - `learning/lerobot/scripts/run.sh`：`prepare-policy`、`convert`、`validate`、
    `filter`、`train`、`bundle`、`verify-bundle`、`budget`、`policy`。
  均支持 `--help` 并把参数继续传给原 CLI。需要 ROS SDK 的命令在容器内先运行
  `dev_workspace.py check`；runtime/learning 的 Policy 业务先运行
  `policy_sdk.py check`。公共 shell 入口不预检尚未生成的 SDK。`collect`/`policy`
  必须显式给每个 run 的 `--output /data/raw/<run-id>`；`test` 固定
  `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1`，避免 ROS 自动插件提前导入 Torch 测试。
- 准备逻辑从 `stack_once.py` 拆出，不再调用 Docker：
  - learning `prepare_policy.py` 校验真实 ACT bundle，生成通用
    `policy_binding.json`、可执行 `policy.yaml`、`act_contract.json` 和
    `run_manifest.json`；模型/processor/profile/schema 摘要全部来自 bundle 与
    shipped 文件。
  - runtime `prepare_run.py` 只消费通用 JSON、runtime 模板、seed/run-id，写出
    `runtime.yaml` 和 `run_manifest.json`；不导入 `dual_arm_learning`、MuJoCo 或
    ROS。只要求通用 `bundle_digest`/`processor_digest`，直接设置已知 policy 字段；
    endpoint 允许配置 host:port，但端口必须与声明 `service.port` 一致；绑定
    `run_id` 必须与当前 run-id 一致；模板残留未解析占位即失败。
  - simulation `prepare_backend.py` 负责本端 backend 配置与 seed，输出显式目录。
  三者均拒绝覆盖已存在的输出目录。
- 保留并归位纯业务能力：`stack_campaign.py` 的追加式预算台账、`stack_export.py`
  的标签/RGB/质量导出、`stack_evaluate.py` 的只读评估仍在 runtime；campaign 的
  launch/cleanup 命令显式拒绝 `docker`/`podman`/`env.sh`。`learning.py` 与
  `act_policy.py` 薄入口迁到 learning 端。
- Dockerfile 运行 target 的 `CMD` 全部改为空闲，未声明匿名 `VOLUME`；删除 Compose
  业务 overlay、宿主 Docker 启动器、旧 host build wrapper 和入口预检 SDK 的脚本。
  Dockerfile 仍只 COPY 锁文件/依赖元数据，不 COPY 业务源码。Policy SDK 生成器从
  `tools/contracts/` 移到 `infrastructure/scripts/generate_policy_sdk.py`，空
  `tools/` 目录和说明清除。
- `check_dockerfiles.py` 扫描三端全部 Dockerfile，拒绝业务 COPY、内嵌 heredoc/
  `python -c`/shell 控制流/大段 RUN、业务 CMD 和匿名 VOLUME；同时检查根 include
  与三端 Compose 的 idle command、绝对 bind source、`/workspace/var`/`.build` 可写、
  无 healthcheck/Docker socket、learning 无 ROS、runtime 无 GPU、simulation NVIDIA
  渲染及项目派生网络名。
- 删除清单在 `.build/reports/dsh-053/cleanup.json`，包括旧 overlay、宿主启动器、
  host build wrapper、仅验证旧启动器的测试，以及保留测试中删除的具体宿主用例。
  数据、模型、报告、缓存、历史正文和实验证据未删除。
