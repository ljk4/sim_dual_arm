# DSH-050：Ruckig 亚纳秒制动前缀的数值导出修复

## 真实失败与范围

30502在用户批准的0.30rad/0.04m策略参考偏差预算、2s稳定等待、0.5s窗口+时间融合下完成29次真实预测，实测夹爪约0.03982m，已有手指接触。第29块因 INVALID_RUCKIG_EXPORT 停车：导出器拒绝任何非零brake前缀。

主助手从真实MCAP重建该请求（不推进物理）：right_gripper轴15起始速度0.04000000000000001m/s，比上限0.04m/s高一个舍入量。Ruckig0.15.3生成的brake.duration=2.2013877787807815e-14s（约22飞秒），t=[该值,0]、a=[-0.5,0]、j=[0,0]；位置变化约8.8e-16m、速度变化约1.1e-14m/s。主轨迹总时长0.5s，不需要真实额外的一个纳秒。证据 `.build/reports/dsh-048/brake-probe.json`。

Ruckig官方v0.15.3的 brake.hpp 与 trajectory.hpp确认前缀在主段之前积分。参考 https://github.com/pantor/ruckig/blob/v0.15.3/include/ruckig/brake.hpp 与 https://github.com/pantor/ruckig/blob/v0.15.3/include/ruckig/trajectory.hpp 。本阶段不扩大到支持有意义的非零制动段，不改变Ruckig调用次数、硬限位、参考偏差/实测跟踪或成功判定。

## DSH实现任务

白名单：components/backend_sim/src/robot_backend_sim/ruckig_export.py、tests/unit/test_follower_plan.py（或最多新增明确test_ruckig_export.py）、docs/history/dsh-050.md、自有.build报告。禁止改follower/controller/模型/配置/协议/其他源码，不Docker/仿真/训练/联网/Git add/commit/删除。

把“所有非零brake一律拒绝”改为一个小的具名验证/折叠函数：仅允许在现有纳秒量化下总时长round为0ns的二阶前缀。总duration和两段t必须finite、非负、和一致；只有第一段有效、第二段0、第一段j=0；有效p/v/a/j有限。验证积分的起止位置/速度变化均不超当前已有_BOUNDARY_ATOL=1e-9，末态必须与主profile的初始p/v在已有误差范围内一致。不得简单忽略小duration而不查状态变化；未初始化的零时长padding无需读取。真正可表示的非零ns前缀、负数、NaN、非零jerk、数组错误、巨大状态跳变仍明确拒绝。

折叠后第一有效导出phase的起始p/v应保留brake的原起始值，确保继承anchor的C1；主段时间轴不额外增加ns，其余phase和旧零brake路径不变。不要改变已有容差、不做Ruckig输入速度裁剪、不追加Ruckig调用，不做通用多段brake导出。

回归：真实Ruckig二阶1DOF（可参考上述起始状态，在0.5s minimum_duration上目标为可达正位置、max_acc=.5、max_vel=.04、max_jerk=inf）应复现tiny brake；导出与trajectory.at_time在0、phase边界、2ms ticks和最终/截断点的p/v相符（使用已有容差），初始p/v精确保留。普通零前缀路径不变；真实非零制动、负/NaN、可表示duration、巨大状态变化必须拒绝。可以用简单typed fixture构造非法公共profile；不要伪造Ruckig结果声称物理通过。保留原测试，运行目标回归、Ruff和diff检查。主助手独立重建16DOF失败请求并执行后续仿真。

## 实现结果

- `ruckig_export.py`：原来的“任何非零brake一律拒绝”替换为具名
  `_fold_tiny_brake_prefix()`。它只接受总duration在既有`_round_ns`量化下为
  `0ns`、两段t有限非负且和等于duration、第一段非空且j=0、第二段为空、
  p/v/a/j各恰好两个公共项且第一项有限、第一段(j=0)积分的起止p/v变化不超
  `_BOUNDARY_ATOL=1e-9`、积分末态与主profile初始p/v相差不超`1e-9`的二阶前缀。
  零时长第二段的padding值不读取；表示上真正非零的ns前缀、负/NaN、非零jerk、
  数组长度错误、非空第二段、时长和错误及巨大状态跳变仍拒绝。
- 折叠只发生在纳秒分配完成后：第一有效导出phase的`start_s`重置到全局0并保留
  brake原起始p/v，`start_ns/end_ns`与主时间轴不变；其余phase及旧零brake路径
  未改。未做Ruckig输入速度裁剪、未增加Ruckig调用、未改容差或做成通用多段
  brake导出。
- 测试：真实Ruckig 0.15.3二阶1DOF复现22飞秒brake，覆盖原起始状态和目标
  0.01665229386424162/0.03（后者还包含一个亚纳秒主phase，需折叠到下一个有效
  phase）；在0、每2ms、导出phase边界、完整/250ms截断点与`trajectory.at_time`
  比较p/v，最大误差约`2.1e-10`，初始p/v逐位保留。另用typed fixture覆盖零时长
  padding不读取、旧零brake路径、可表示1ns、负/NaN、非零jerk、数组错误、
  非空第二段、时长和不一致及巨大状态变化拒绝。
