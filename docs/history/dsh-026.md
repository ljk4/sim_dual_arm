#### 请求与模式

共享 `NativeRequest` 包含既有 `Trajectory`（context/lease/command/seq/observation/deadline、joint_names和完整source targets），
以及kind、可选ChunkAnchor、observation_time_ns、target_count、settle_at_end、可选final_velocities。
冻结且深规范化。共享ControlCommand负责身份校验；源路点1..128、轴1..64、正递增时间且horizon≤3s、维数一致、有限实数且拒bool。
header/frame/额外velocity/acceleration/effort等不支持语义在ROS转换中明确拒绝，不静默丢字段。

三种模式明确区分：

1. MOTION=1：源时间相对本次实际STARTED，使用既有prepare_motion零起止速度。anchor=None、observation_time_ns=0、target_count=0、settle_at_end=True、final_velocities=None；拒非默认的无意义字段。实际初始参考由调用方提供最后hold参考，不能使用测量重定基。
2. STREAM_FIRST=2：anchor.predecessor_seq=0、窗口时间相对**源观测捕获时刻**、其余语义沿用ActionWindow/prepare_chunk。
3. STREAM_NEXT=3：同一整体command_id/seq，anchor.predecessor_seq>0，observation_id可变但与窗口匹配。

stream只在固定handoff选择严格未来点，完整源（含不执行前缀/尾部）不隐藏坏数值或坏限位；不retime。
共享DTO做结构校验；profile关节/速度/加速度/连续极值由后续预编译及参考记录验证负责。
整型边界与ControlCommand一致（身份正数、时间非负int64；bool拒绝）。None在wire上用显式has_*或约定的空可选字段表达，真实0时刻不能当成未started。

#### 新ROS类型（名称固定）

| 类型 | 字段语义 |
| --- | --- |
| `ReferenceAnchor.msg` | stream_id、predecessor_seq、start_sim_time_ns(int64)、robot_profile_hash、positions/velocities/accelerations，数组≤64 |
| `NativeCommand.msg` | 常量MOTION=1/STREAM_FIRST=2/STREAM_NEXT=3及kind；旧TrajectoryCommand command；ReferenceAnchor anchor；observation_time_ns；target_count；settle_at_end；has_final_velocities及final_velocities≤64 |
| `ReferenceSegment.msg` | duration_ns和c0/c1/c2/c3各≤64；p(s)=c0+c1*s+c2*s²+c3*s³，s为局部秒，不能倒置SciPy系数顺序 |
| `AcceptedReference.msg` | 原NativeCommand request、motion_seq、accepted_sim_time_ns、joint_names≤64、ReferenceSegment segments≤128、initial_positions/initial_velocities/final_velocities/max_accelerations各≤64、selected_indices≤128、reference_digest、interpolation_version固定explicit_cubic_v1 |
| `NativeFinger.msg` | side、finger_index(1/2)、body_name、joint_speed_m_s；object_names/normal_forces/contact_counts三个等长有界数组≤8，保留每物体的合力与计数，不只传单个contact布尔值 |
| `NativeGripper.msg` | side、mode(NONE/POSITION/CONTACT)、position_ok/contact_ok/contact_object/ambiguous、原target/initial/final_reference、实测总开度/速度/误差、两个NativeFinger |
| `NativeExecution.msg` | 完整context/整体command_id/seq/初始observation_id；整体phase/reason/stop_reason；motion_seq、stream_id、当前实际chunk_seq(0表示未应用块)；accepted/start/finish sim与wall字段及has_started/has_finished；真实motion_phase；reference_application_sim_time_ns、measurement_sim_time_ns、reference_elapsed_ns、stable_for_ns；joint_names、参考p/v/a、测量p/v、位置/速度误差；reference_kind、tracking_quality/violation_ns；两只NativeGripper |
| `NativeChunkStatus.msg` | context/command_id/seq/chunk_seq/observation_id、phase/reason、accepted/start/finish sim与wall和has_started/has_finished；不把RETIRED称为运动COMPLETED |
| `NativeControlEvent.msg` | ControlEvent原context、event_seq、command_id/seq/observation_id、is_chunk/chunk_seq、phase/reason、sim_time_ns；不生成新的身份/时间 |
| `SubmitNative.srv` | request NativeCommand；response accepted/reason、has_execution/NativeExecution、has_chunk/NativeChunkStatus、has_reference/AcceptedReference |
| `GetNativeAnchor.srv` | request context/lease_id、has_start/start_sim_time_ns；response success/reason/ReferenceAnchor |
| `QueryNativeCommand.srv` | request context/command_id；response success/reason/NativeExecution |
| `QueryNativeChunk.srv` | request context/command_id/chunk_seq；response success/reason/NativeChunkStatus |
| `ResetSimulation.srv` | request context/lease_id/seed(uint64，执行限制按既有validate_seed)；response success/reason/new_context |

所有新序列尽量使用ROS bounded sequence；编码/解码严格验证长度/范围/有限性/模式/has字段，而不是相信生成类。旧19个契约源中现存msg/srv/action字节保持，只允许CMake新增注册。
NativeExecution的整体terminal必须取ControlStatus冻结snapshot；后续RobotState实时测量不写回已冻结terminal，也不带新context冒充旧命令反馈。stream当前来源观测通过chunk_seq与AcceptedReference关联，整体observation_id保持最初引用。
Acquire/Renew/Release/Stop复用现有服务，不重复定义。ResetSimulation是可选仿真能力；不要求真机实现。

#### 可审计参考记录

共享 `AcceptedReference` 保存NativeRequest、显式ReferencePlan、实际边界速度/初值/最大加速度、选中索引、accepted时刻和motion_seq。
完整原请求不被改成selected targets。reference_digest来自本公开DTO的稳定canonical JSON（格式有版本，非有限拒绝），包含请求/全部系数/时间/身份；不复用不可独立解析的backend私有对象哈希。

提供标准库 `validate_accepted_reference(record, profile, max_accelerations)`，复用现有verify_reference_plan/validate_reference_inputs：

- 关节/单位/配置顺序与profile一致，完整源所有点限位通过，实际系数通过连续p/v/a极值限制。
- MOTION初末速度0，selected_indices为空，初值等于记录的实际参考初值。
- STREAM由ActionWindow重新计算selected_indices和局部targets，anchor p/v匹配计划；explicit末速度按请求，None按最后两点后向差分，final settle强制0。
- reference_digest校验，拒时间/目标/系数/身份/selection/末端模式被篡改。跨块只声明p/v连续，不声称a连续。
- 不要求accepted_at已等于实际started。MOTION的实际计划零点来自后续NativeExecution.started_sim；STREAM计划零点是anchor的固定绝对时刻。

提供按绝对应用时刻重建记录参考的清楚函数，MOTION显式传actual_started_sim_ns；STREAM从anchor取start。
非final stream过horizon必须REFERENCE_EXPIRED；final零速末端可显式HOLD，不能为未续接块自动零速。BRAKE不伪装成原normal计划，完整取消审计留后续接线，反馈原p/v/a与实际类型仍保留。

#### 反馈DTO与backend适配

NativeExecution共享DTO包含上表真实字段，冻结/深不可变；校验context身份、合法phase/模式、数组顺序/长度、实数、时间/flags、误差=参考−测量。
夹爪保留原目标和实测误差；CONTACT不是物体堆叠成功。NativeFinger的force非负、count整数、object_names唯一，与side/index一致。
不要把boolean转float、空started转0后丢失has_started、或让查询改测量。只检验传输结构/不变量，不在contracts里重新实现物理接触算法。

backend `protocol.py` 至少提供：

- `prepare_request(request, profile, control_config, *, initial_reference=None) -> PreparedControlCommand`，只有MOTION需要明确提供hold初值，stream从anchor取；在规划调用方运行，不读Scene。
- `accepted_reference(request, packet, accepted_snapshot)`，绑定实际预编译packet/接受事实，拒request与packet不对应；输出共享可审计记录。
- `execution_feedback(ControlStatus)`、`chunk_feedback(ChunkStatus)`、`control_event(ControlEvent)`，不改源对象、不读隐藏clock/物理真值。

ROS native_conversions提供每个公开DTO的显式双向函数，异常均为稳定ContractError，不吞错误。
没有ROS服务/队列/线程实现，没有MCAP writer，也不提前宣称Native capability已上线。

### 原生参考与反馈公共类型

DSH-026 定义传输无关的原生请求、可审计参考记录和反馈 DTO。当前只提供类型、
校验与显式 ROS 转换；没有新增 ROS 服务实现、队列、线程、MCAP writer，也尚未
声明 Native capability 已上线。

#### 模块与边界

| 模块 | 职责 |
| --- | --- |
| `robot_contracts/native_reference.py` | `NativeRequest`、`AcceptedReference`、canonical digest、独立校验与按绝对时刻重建 |
| `robot_contracts/native_feedback.py` | `NativeFinger`、`NativeGripper`、`NativeExecution`、`NativeChunkStatus`、`NativeControlEvent` |
| `robot_contracts/native.py` | 稳定导入点，re-export 上述公共值 |
| `robot_ros_support/native_conversions.py` | 每个公共 DTO 的显式双向 ROS 转换 |
| `robot_backend_sim/protocol.py` | `prepare_request`、`accepted_reference`、`execution_feedback`、`chunk_feedback`、`control_event` |

共享 DTO 只依赖标准库和既有 `robot_contracts`。参考数学继续使用既有
`ReferencePlan`/`CubicSegment`/`ActionWindow`，没有第二套插值或极值算法。
`native_reference.py` 与 `native_feedback.py` 不导入 ROS、backend、MuJoCo、
SciPy 或 NumPy。`protocol.py` 不导入 ROS、不写盘、不步进、不创建线程。

#### 模式

`NativeRequest` 包装既有 `Trajectory`（context、lease、command id/seq、
observation、deadline、joint_names、完整 source targets）以及：

| 字段 | MOTION=1 | STREAM_FIRST=2 | STREAM_NEXT=3 |
| --- | --- | --- | --- |
| `anchor` | `None` | `ChunkAnchor`，`predecessor_seq=0` | `ChunkAnchor`，`predecessor_seq>0` |
| `observation_time_ns` | 0 | 源观测捕获的绝对时刻 | 源观测捕获的绝对时刻 |
| `target_count` | 0 | 2..128 | 2..128 |
| `settle_at_end` | 必须 true | 可选 | 可选 |
| `final_velocities` | 必须 `None` | `None` 或显式向量 | `None` 或显式向量 |

- **MOTION**：source 时间相对本次实际 `STARTED`。调用方必须提供最后 hold
  参考；使用既有 `prepare_motion`，初末速度均为零。不能以测量重定基。
- **STREAM_FIRST / STREAM_NEXT**：source 时间相对源观测捕获时刻；
  `anchor.start_sim_time_ns` 是固定绝对 hand-off。`ActionWindow` 只选择严格晚于
  hand-off 的前 `target_count` 个点；完整 source（含不执行前缀/尾部）保留且
  校验，坏限位或坏数值不能被窗口隐藏。不 retime。
- 同一整体 stream 保持 command id/seq；每个后继请求的 `observation_id` 可变，
  但必须等于其窗口观测。跨块只声明 p/v 连续，不声明 a 连续。

#### 时间与系数约定

- 所有时间、持续时间、超时均为整数纳秒；`int64` 非负，身份/序列为正整数。
  布尔值不会被当作整数接收。
- 多项式使用局部秒 `s` 和升幂系数：
  `p(s)=c0+c1*s+c2*s^2+c3*s^3`。
  不是 SciPy 的降幂 `c[k]` 顺序。
- `ReferencePlan` 是显式分段三次计划；`duration_ns` 为正，horizon ≤ 3 s，
  最多 128 段、64 轴。
- `ReferenceSample` 的 positions/velocities/accelerations 都在同一关节顺序下。
- 真实时刻 0 是合法时间；可选状态用 `None` 或显式 `has_*` 表达，不能把
  “未 started” 与 `started_sim_time_ns=0` 混为一谈。

#### 可审计参考记录

`AcceptedReference` 保存：

- 原始 `NativeRequest`（完整 source，不被 selected targets 替换）；
- `motion_seq`、`accepted_sim_time_ns`；
- joint_names 与显式 `ReferencePlan`；
- 实际边界 `initial_positions`/`initial_velocities`/`final_velocities`、
  `max_accelerations`；
- `selected_indices`；
- `interpolation_version="explicit_cubic_v1"`；
- `reference_digest`。

`reference_digest` 是公开 DTO 的稳定 canonical JSON 的 SHA-256，格式版本为
`native-reference-v1`，覆盖请求身份、完整 source、anchor、全部 segment 系数、
时间、选择、边界和末端模式。它不是 backend 私有对象的哈希。构造时若未提供
digest 会自动生成；提供时立即校验，篡改会在反序列化/构造阶段以
`REFERENCE_DIGEST_MISMATCH` 拒绝。

`validate_accepted_reference(record, profile, max_accelerations)` 复用
`validate_reference_inputs` 和 `verify_reference_plan`：

- 关节/单位顺序与 profile 一致，完整 source 全部点通过限位；
- 实际系数通过连续 p/v/a 极值限制；
- MOTION 初末速度为 0、`selected_indices` 为空；
- STREAM 用 `ActionWindow` 重新计算 selection 和局部 targets，anchor p/v
  与计划起点一致；显式末速度按请求，`None` 按最后两个选中点后向差分，
  `settle_at_end=True` 强制零速；
- digest 再次重算，拒绝时间/目标/系数/身份/selection/末端模式篡改；
- `accepted_at` 不要求等于实际 started。MOTION 的实际计划零点来自后续
  `NativeExecution.started_sim`；STREAM 计划零点是 anchor 固定绝对时刻。

`sample_accepted_reference(record, sim_time_ns, *, actual_started_sim_ns=...)`
按绝对应用时刻重建参考。MOTION 必须显式传实际 started；其已声明 final 模式为
末端 hold，horizon 之后返回末目标 p 与 v=0/a=0（NativeMotion 实际也继续采样
末目标并等待实测稳定），起点之前仍严格 `REFERENCE_EXPIRED`。STREAM 从 anchor
取零点；非 final stream 超出 horizon 抛 `REFERENCE_EXPIRED`；final 零速 stream
可显式 HOLD 末端，未续接块不会被自动补零。

BRAKE 不伪装成原 normal 计划。完整取消审计留给后续接线；反馈仍保留实际
p/v/a 和真实 `reference_kind`。

#### 反馈 DTO

- `NativeFinger`：side、finger_index(1/2)、body_name、joint_speed_m_s，以及
  三个等长有界数组 `object_names`/`normal_forces`/`contact_counts`（≤8）。
  保留每物体合力与计数，不只传单个 contact bool。force 非负、count 为非负
  整数、object_names 唯一。
- `NativeGripper`：side、mode(NONE/POSITION/CONTACT)、position_ok/contact_ok/
  contact_object/ambiguous、原 target/initial/final_reference、实测总开度/
  速度/误差、两个 `NativeFinger`。CONTACT 只表示接触模式，不表示物体堆叠成功。
- `NativeExecution`：完整 context、整体 command id/seq、初始 observation_id；
  整体 phase/reason/stop_reason；motion_seq、stream_id、当前实际 chunk_seq
  （0 表示未应用块）；accepted/start/finish sim 与 wall 及 has_started/
  has_finished；真实 motion_phase；reference application/measurement/elapsed/
  stable 时间；joint_names、参考 p/v/a、测量 p/v、位置/速度误差；reference_kind、
  tracking_quality/violation_ns；左右两个 `NativeGripper`。
  误差必须等于参考−测量。terminal 反馈只取 `ControlStatus` 冻结 snapshot，
  后续 `RobotState` 实时测量不写回。
- `NativeChunkStatus`：保留真实 chunk phase；`RETIRED` 不会改写成运动
  `COMPLETED`。
- `NativeControlEvent`：复制 `ControlEvent` 的 context/event_seq/command id/seq/
  observation_id/is_chunk/chunk_seq/phase/reason/sim_time_ns，不生成新身份或时间。

`protocol.py`：

```python
prepare_request(request, profile, control_config, *, initial_reference=None)
accepted_reference(request, packet, accepted_snapshot)
execution_feedback(control_status)
chunk_feedback(chunk_status)
control_event(control_event)
```

`prepare_request` 在规划调用方运行，不读 Scene。MOTION 只接受显式 hold 初值；
stream 从 anchor 取。`accepted_reference` 拒绝 request 与已编译 packet 不对应。

#### 新 ROS 类型

消息：`ReferenceAnchor`、`NativeCommand`、`ReferenceSegment`、
`AcceptedReference`、`NativeFinger`、`NativeGripper`、`NativeExecution`、
`NativeChunkStatus`、`NativeControlEvent`。

服务：`SubmitNative`、`GetNativeAnchor`、`QueryNativeCommand`、
`QueryNativeChunk`、`ResetSimulation`。Acquire/Renew/Release/Stop 继续复用
既有服务。`ResetSimulation` 是可选仿真能力，不要求真机实现。

数组尽量使用 ROS bounded sequence；`NativeFinger`/`NativeGripper` 固定两个手
指/夹爪。`NativeCommand.anchor.stream_id` 为空是 MOTION 的“无 anchor”约定；
`has_final_velocities` 为 false 时 `final_velocities` 必须为空。转换器不信任
生成类：重复校验长度/范围/有限性/模式/has 字段，并明确拒绝非零 header、
非空 frame、point velocity/acceleration/effort 等不支持语义，不静默丢字段。
所有异常均为稳定 `ContractError`。

#### 验证入口

- `tests/unit/test_native_contracts.py`
- `tests/unit/test_native_reference_record.py`
- `tests/integration/test_native_protocol_ros.py`
- `tests/integration/test_native_protocol_physics.py`

host 无 ROS/native/SciPy 时后两者按既有测试约定 skip；固定镜像/原生 SDK 下由
监督者执行真实序列化和物理对照。旧 msg/srv/action 源字节保持不变，只更新
`robot_api_msgs` 的 CMake 注册。


实际参考类型在首次轨迹应用前为 HOLD，普通运动有效区间为 TRAJECTORY，区间后明确
保持末端为 HOLD；连续块有效区间为 CHUNK。停止失败沿用最近真正应用的类型，不能
因仅创建了刹车计划就标为 BRAKE。该区分只修正反馈事实，不改变控制参考或限位。
接触传输验收复用运行前预载的自由块夹持夹具，目标0与实测约4cm分别保留，不计正式数据。
