# 功能说明

按功能说明系统的职责、实现流程、输入输出、接口和使用边界，帮助维护者从一个
具体能力找到相关模块、配置与代码。一个完整功能一份文档；同一功能涉及多个
模块时，在同一文档中说明它们如何协作。

## 组织方式

- 文件使用简短的英文主题名，例如 `action-execution.md`、`act-training.md`。
  文件名示例仅用于说明命名，本次不创建这些文档。
- 每篇聚焦一个可独立理解和验证的功能，列出涉及模块及各自责任。功能粒度在
  编写前确定，避免同一能力在多篇文档中重复维护。
- 描述当前实现，明确已实现、待验证或计划中的部分；实现变化时同步更新。
  代码、契约和配置仍是行为与参数的依据，文档链接到它们，不复制一套参数来源。

## 后续每篇建议包含

1. 功能目的、适用场景与职责范围。
2. 参与模块、主要流程、状态与资源所有权。
3. 输入输出、通信接口、字段语义、单位和时序；适用时说明 ACK 与反馈。
4. 关键配置、前置条件、使用入口与验证方法。
5. 错误处理、失败表现和已知限制。
6. 相关代码、契约、配置及历史/实践记录的定位链接。

根 README 提供项目级使用指南，各源码目录 README 说明本地用途；本目录展开
功能细节。[阶段历史](../history/README.md)保留实施过程，
[重要实践](../experiments/README.md)提炼经过确认的尝试和经验。
