# 脚本入口与使用指南

本文档汇总仓库内全部宿主机入口与三端容器脚本的适用范围、命令行参数、输入输出路径及常用示例，内容与当前脚本实现保持同步。

> **状态区分（文档内标注）**
> - **本轮已落地**：宿主机容器管理与并行调度入口（`env.sh`、`record_parallel.sh`、`inference_parallel.sh`）、三端业务与测试脚本（`simulation/mujoco/scripts/*.sh`、`runtime/ros2/scripts/*.sh`、`learning/lerobot/scripts/*.sh`）。
> - **后续期望落地**：真机硬件端（`hardware/`）接入对应的独立运行脚本。

---

## 0. 执行边界与脚本总览

### 0.1 执行环境边界

- **宿主机脚本**（仓库根目录 `./env.sh`、`./record_parallel.sh`、`./inference_parallel.sh`）：必须在**宿主机项目根目录**执行；`record_parallel.sh` 与 `inference_parallel.sh` 在容器内（`PROJECT_CONTAINER=1`）直接执行会报错退出（返回码 `2`）。
- **容器内脚本**（三端 `scripts/*.sh`）：通过 `shared/common/tools/docker/setup.sh` 校验容器环境，必须在对应容器内执行（或由宿主机通过 `./env.sh exec <env> scripts/...` 转发）；在宿主机直接运行会报错退出（返回码 `2`）。
- **云端无 Docker 学习端**：在仅配置 `uv` 虚拟环境的远端 GPU 机器上，先按 [Learning 使用说明](../../learning/lerobot/README.md) 执行 `source .env.learning`，再直接以 `bash learning/lerobot/scripts/<script>.sh ...` 运行转换、训练或策略服务脚本。

### 0.3 通用约定

1. **方案选择与直接配置互斥**：各业务脚本支持 `--robot <robot-id> --task <task-id>`（可选 `--shared-root <dir>`）从 `shared/scenarios/<robot-id>/<task-id>/binding.yaml` 在内存展开配方；也可使用 `--config <path>` 等直接配置参数，两者互斥。
2. **产物路径隔离**：方案模式写入 `var/<robot-id>/<task-id>/`（容器内 `/data/<robot-id>/<task-id>/`）；直接配置模式统一写入 `var/_direct/`（容器内 `/data/_direct/`）。
3. **时间戳与防重名**：默认生成的 `run-id`、批次目录名与日志文件名自动附加 `_YYYYMMDD_HHMMSS` 后缀；若同秒重复触发，自动追加 `_2`、`_3` 避免冲突或覆盖。

## 1. 宿主机入口脚本（仓库根目录）

### 1.1 容器与可视化管理：`./env.sh`

统一管理 `runtime`、`simulation`、`learning`、`hardware` 四个 Docker Compose 服务（共享项目名 `sim-dual-arm`）。

#### 子命令与参数

| 子命令 / 用法 | 说明 |
| :--- | :--- |
| `./env.sh <env>` | 复用本地镜像、后台启动并进入 `<env>` 容器交互式 `bash`（等同 `enter <env>`） |
| `./env.sh enter <env>` | 后台启动已有镜像并进入容器 `bash` |
| `./env.sh up <env>` | 后台启动容器（固定 `--no-build --pull never`），并确保宿主机 `build/ros-dev`、`build/generated/policy-sdk`、`var` 目录存在 |
| `./env.sh build <env>` | 显式构建指定环境镜像（首次使用或 `Dockerfile`/依赖变更时执行） |
| `./env.sh exec <env> [cmd...]` | 在已运行的 `<env>` 容器内执行指定命令；省略 `[cmd...]` 时打开交互式 `bash` |
| `./env.sh stop <env>` | 停止指定环境容器（不影响其他端容器） |
| `./env.sh rm <env>` | 先停止再强制删除指定环境容器（单端清理，不执行全局 `down --remove-orphans`） |
| `./env.sh viewer <args...>` | 通过一次性 `simulation` 容器挂载宿主机 X11 并调用 `scripts/viewer.sh <args...>` 启动实时可视化；要求已设置 `DISPLAY` 且传入 `--robot <id> --task <id>` |
| `./env.sh ps` | 查看项目 `sim-dual-arm` 下当前所有容器状态 |
| `./env.sh list` | 输出支持的容器环境名：`runtime simulation learning hardware` |
| `./env.sh -h \| --help \| help` | 打印帮助信息 |

可用 `<env>` 取值：`runtime`（`runtime/ros2/docker/docker-compose.yml`）、`simulation`（`simulation/mujoco/docker/docker-compose.yml`）、`learning`（`learning/lerobot/docker/docker-compose.yml`）、`hardware`（`hardware/tianji/docker/docker-compose.yml`）。

#### 使用示例

```bash
# 1. 首次构建镜像并进入 runtime 容器
./env.sh build runtime
./env.sh runtime

# 2. 后台启动全部容器并在宿主机查看状态
./env.sh up simulation
./env.sh up learning
./env.sh ps

# 3. 修改 Compose 挂载配置后重新加载单端容器
./env.sh up simulation

# 4. 不进入交互 shell，直接在容器内执行一条命令
./env.sh exec runtime scripts/record.sh status --robot marvin_sim --task stack
./env.sh exec learning scripts/convert.sh --robot marvin_sim --task stack

# 5. 在宿主机桌面打开只读 MuJoCo 可视化（若报 X11 权限错误，先执行 xhost +SI:localuser:$(id -un)）
./env.sh viewer --robot marvin_sim --task stack
./env.sh viewer --robot marvin_sim --task handover

# 6. 仅停止并移除单端容器
./env.sh rm simulation
```

### 1.2 宿主机并行采集：`./record_parallel.sh`

由宿主机调用 `host.record_parallel`，在 `runtime` 容器内执行前置校验与统一调度，为每个 worker 拉起独立隔离的 `simulation` 容器（独立 ROS Domain ID、命名空间与无头 EGL 渲染，禁用 GUI 可视化与预览 GIF），合格数据持续写入同一台账。

#### 参数列表

| 参数 | 默认值 | 说明与约束 |
| :--- | :--- | :--- |
| `--robot <id>` / `--task <id>` | 无 | 方案模式，需成对传入；与 `--config`/`--runtime-config`/`--backend-template` 互斥 |
| `--shared-root <dir>` | `<project>/shared` | 覆盖方案目录树根路径（仅方案模式可用，需位于宿主机挂载目录内） |
| `--config <path>` | 无 | 直接模式：campaign 配方路径；需与 `--runtime-config`、`--backend-template` 同时传入 |
| `--runtime-config <path>` | 无 | 直接模式：runtime Teacher 配方路径 |
| `--backend-template <path>` | 无 | 直接模式：simulation Teacher 配方模板路径 |
| `--count <N>` | `1`（若未传 `--target-total`） | 本次批次新增合格局目标数（正整数）；与 `--target-total` 互斥 |
| `--target-total <N>` | 无 | 续采至台账累计合格达到 `N` 条（已达标则直接返回 `0`） |
| `--purpose formal\|pilot` | `formal` | 采集用途：`formal` 计入正式清单配额并在达标时写 `formal-select.json`，`pilot` 仅试采 |
| `--workers auto\|<1..16>` | `auto` | 并发 worker 数；`auto` 按 CPU、可用内存与显存估算至多 4 路，且实际并发不超过本次需采条数 |
| `--max-consecutive-failures <N>` | `3` | 单 worker 连续不合格次数上限（各 worker 独立计数，合格一次清零） |
| `--realtime-speed <float>` | `1.0` | 仿真倍速，范围 `(0.1, 100]` |
| `--domain-base <int>` | 随机 `100..(200 - workers)` | 起始 `ROS_DOMAIN_ID`，需保证整批域 ID 位于 `0..232` |
| `--project-root <dir>` | 仓库根目录 | 指定项目根目录 |

#### 使用示例

```bash
# 1. 续采 stack 方案 formal 数据至累计 50 条（断点/异常后可原样重跑）
./record_parallel.sh \
  --robot marvin_sim --task stack \
  --purpose formal --target-total 50 \
  --workers auto --max-consecutive-failures 3

# 2. handover 方案固定 4 路并发再新增 10 条正式数据，并设置 2 倍速仿真
./record_parallel.sh \
  --robot marvin_sim --task handover \
  --purpose formal --count 10 \
  --workers 4 --realtime-speed 2.0

# 3. 2 路并行 pilot 试采 2 条用于快速验证并发链路
./record_parallel.sh \
  --robot marvin_sim --task stack \
  --purpose pilot --count 2 --workers 2 --max-consecutive-failures 2

# 4. 直接配置模式并行采集
./record_parallel.sh \
  --config shared/scenarios/marvin_sim/stack/configs/runtime/collection/campaign_stack.yaml \
  --runtime-config shared/scenarios/marvin_sim/stack/configs/runtime/runtime_stack_teacher.yaml \
  --backend-template shared/scenarios/marvin_sim/stack/configs/simulation/backend/backend_stack_teacher.yaml \
  --purpose pilot --count 2 --workers 2
```

### 1.3 宿主机并行批量推理：`./inference_parallel.sh`

由宿主机调用 `host.inference_parallel`，拉起多路无头隔离 `simulation` worker 与 `runtime` 批量推理器并发评测策略。启动前需先保持 `learning` 端 `scripts/server_policy.sh`（本机或经 SSH 隧道映射）在线；仅支持 MuJoCo 仿真且自动禁用可视化。

#### 参数列表

| 参数 | 默认值 | 说明与约束 |
| :--- | :--- | :--- |
| `--robot <id>` / `--task <id>` | 无 | 方案模式，需成对传入；与 `--runtime-config`/`--backend-template` 互斥 |
| `--shared-root <dir>` | `<project>/shared` | 覆盖方案目录树根路径（仅方案模式可用） |
| `--runtime-config <path>` | 无 | 直接模式：runtime Policy 配方路径；需与 `--backend-template` 同时传入 |
| `--backend-template <path>` | 无 | 直接模式：simulation Policy 配方模板路径 |
| `--count <N>` | `10` | 本批评估总局数（正整数） |
| `--seed-start <int>` | 随机（非负整数） | 起始复位种子（各局按序递增） |
| `--workers auto\|<1..16>` | `auto` | 并发 worker 数，受本次 `--count` 上限裁剪 |
| `--max-consecutive-failures <N>` | 无限制 | 连续失败触发早停的上限 |
| `--policy-endpoint <HOST:PORT>` | 配方默认值 | 覆盖 gRPC Policy 服务地址（默认 `127.0.0.1:50051`，如改用其他本地隧道端口 `127.0.0.1:15051`） |
| `--realtime-speed <float>` | 配方默认值 | 仿真倍速，范围 `(0.1, 100]` |
| `--domain-base <int>` | 随机 `100..(200 - workers)` | 起始 `ROS_DOMAIN_ID`，需保证整批域 ID 位于 `0..232` |
| `--batch-id <id>` | `batch-policy_<YYYYMMDD_HHMMSS>` | 批次标识（1..100 位 `[A-Za-z0-9._-]`） |
| `--project-root <dir>` | 仓库根目录 | 指定项目根目录 |

#### 使用示例

```bash
# 1. 默认并发评估 stack 方案 10 局（seed 从 6000 起）
./inference_parallel.sh \
  --robot marvin_sim --task stack \
  --count 10 --seed-start 6000 --workers auto

# 2. handover 方案指定 2 路并发、自定义批次号与连续失败保护
./inference_parallel.sh \
  --robot marvin_sim --task handover \
  --count 20 --seed-start 5100 --workers 2 \
  --max-consecutive-failures 5 --batch-id eval_handover_v1

# 3. 连接转发到其他本地端口（如 15051）的远端 GPU 策略服务
./inference_parallel.sh \
  --robot marvin_sim --task stack \
  --count 10 --workers auto \
  --policy-endpoint 127.0.0.1:15051
```

评估完成后，逐局录制与控制台日志位于 `var/<robot>/<task>/logs/batch-policy/<batch-id>/`，统计报告写入 `var/<robot>/<task>/debug/batch-policy/<batch-id>/report.json`。

## 2. `runtime` 容器脚本（`runtime/ros2/scripts/`）

以下脚本在 `runtime` 容器内（工作目录 `/app`）以 `scripts/<name>.sh` 运行，或由宿主机通过 `./env.sh exec runtime scripts/<name>.sh` 调用。

### 2.1 SDK 构建：`scripts/build_sdk.sh`

编译跨端 ROS 2 接口工作空间（`shared/common/interfaces/ros/*` 与全部 `shared/scenarios/*/*/extensions/ros/*`）至 `/build/ros-dev`，以及生成 Policy Protobuf/gRPC Python SDK 至 `/build/generated/policy-sdk`。

| 参数 | 说明 |
| :--- | :--- |
| （无参数） | 同时构建 ROS 2 接口工作空间与 Policy SDK |
| `--ros-only` | 仅构建 ROS 2 接口工作空间（`/build/ros-dev`） |
| `--policy-only` | 仅生成 Policy Protobuf/gRPC Python SDK（`/build/generated/policy-sdk`） |
| `-h` / `--help` / `help` | 打印帮助并退出 |

```bash
# 全量构建两个 SDK
scripts/build_sdk.sh

# 仅更新 Policy proto 后重新生成 Python SDK
scripts/build_sdk.sh --policy-only

# 仅更新 ROS 2 msg/srv IDL 后重新编译 ROS 接口工作空间
scripts/build_sdk.sh --ros-only
```

### 2.2 单路示教采集与台账查询：`scripts/record.sh`

对应 `dual_arm_runtime.offline.collection.record`，包含**采集模式**（默认）与**状态查询模式**（`status`）。执行采集前需先在 `simulation` 容器启动 `teacher_backend.sh`（或 `backend.sh --role teacher`）并等待 `ready.json` 就绪。

#### 采集模式参数

| 参数 | 默认值 | 说明 |
| :--- | :--- | :--- |
| `--robot <id>` / `--task <id>` | 无 | 方案模式（可选 `--shared-root <dir>`）；与 `--config` / `--runtime-config` 互斥 |
| `--config <path>` / `--runtime-config <path>` | 无 | 直接配置模式：campaign 配方与 runtime Teacher 配方（需成对传入） |
| `--purpose formal\|pilot` | `formal` | `formal` 计入正式目标并在达标时写出 `formal-select.json`；`pilot` 仅验证且不入正式清单 |
| `--count <N>` | `1` | 本次运行需新增的**合格** episode 数（不含失败重试） |
| `--max-consecutive-failures <N>` | `3` | 连续不合格上限（合格一次后清零；达到上限退出码为 `1`） |
| `--backend-log <dir>` | 自动定位最新 Teacher 后端 `log/` | 显式传入后端启动时打印的 `log` 目录（多后端实例或自定义 `run-id` 时使用） |
| `--binding-sha256 <hex>` | 无 | 可选校验 binding 摘要（仅方案模式） |
| `--project-root <dir>` | `/app`（脚本默认注入） | 指定项目根目录 |

常见退出码：`0` 目标达成；`1` 连续失败达到上限或尝试未完整结束；`2` 参数错误、预检失败或预算/目录错误；`130` 收到中断信号（`Ctrl-C`）。

#### 状态查询模式（`scripts/record.sh status`）参数

接受 `--robot <id> --task <id>`（可选 `--shared-root <dir>`）或 `--config <campaign.yaml>`，展示 `formal` / `pilot` 进度、尝试统计、原始数据磁盘配额占用及 `formal-select.json` 状态。

#### 使用示例

```bash
# 1. 试采 1 条验证全链路（合格即止，失败 1 次也立即停止）
scripts/record.sh \
  --robot marvin_sim --task stack \
  --purpose pilot --count 1 --max-consecutive-failures 1

# 2. 单路正式新增采集 5 条（允许最多连续失败 3 次）
scripts/record.sh \
  --robot marvin_sim --task handover \
  --purpose formal --count 5 --max-consecutive-failures 3

# 3. 显式指定自定义 backend 的 log 目录
scripts/record.sh \
  --robot marvin_sim --task stack \
  --purpose pilot --count 1 \
  --backend-log /data/marvin_sim/stack/logs/backend/my-teacher/log

# 4. 查看当前采集进度与合格清单状态
```

### 2.3 非交互式单局策略推理：`scripts/client_policy.sh`

校验 `/build/ros-dev` 与 `/build/generated/policy-sdk` 后，以 `--once` 模式运行 `dual_arm_runtime.runtime_node` 完成单局推理与 MCAP 录制并自动退出。运行前需保证 `server_policy.sh` 与 `inference_backend.sh`（或对应后端）均在线。

#### 主要参数

| 参数 | 默认值 | 说明 |
| :--- | :--- | :--- |
| `--robot <id>` / `--task <id>` | 无 | 方案模式，与 `--config` 互斥 |
| `--role policy\|teacher` | `policy` | 方案角色 |
| `--shared-root <dir>` | `/shared` | 覆盖方案目录树根路径（仅方案模式） |
| `--config <runtime.yaml>` | 无 | 直接配置模式：runtime YAML 配方路径 |
| `--policy-endpoint <HOST:PORT>` | 配方默认值 | 覆盖 gRPC Policy 服务地址 |
| `--reset-seed <int>` | 随机 | 场景/复位随机种子（范围 `0..2^63-1`） |
| `--run-id <id>` | `policy_<YYYYMMDD_HHMMSS>` | 本次运行标识（同秒冲突自动加 `_2`、`_3`） |
| `--episode-id <id>` | 同 `--run-id` | 本局录制子目录名 |
| `--output <dir>` | `/data/<robot>/<task>/logs/recordings` | 录制输出根目录（direct 模式为 `/data/_direct/logs/recordings`） |
| `--episode-dir <dir>` | `<output>/<episode-id>` | 直接指定本局录制最终输出目录 |

| `--shutdown-timeout <sec>` | `20.0` | 收到终止信号后等待收尾的最大秒数 |

#### 使用示例

```bash
# 1. 按方案执行一局标准策略推理（随机生成 seed）

scripts/client_policy.sh \
  --robot marvin_sim --task stack \
  --reset-seed 6000 --run-id eval_seed6000 \
  --policy-endpoint 127.0.0.1:15051

# 3. 直接配置模式回放或测试指定 runtime 配方
scripts/client_policy.sh \
  --config /data/marvin_sim/stack/debug/replay_runtime.yaml \
  --reset-seed 1001 \
  --output /data/marvin_sim/stack/debug/recordings
```

### 2.4 交互式单局闭环：`scripts/client_interactive.sh`

## 3. `simulation` 容器脚本（`simulation/mujoco/scripts/`）

### 3.1 统一仿真后端入口：`scripts/backend.sh`

## 6. 常见参数易错点速查

| 场景 / 现象 | 原因说明 | 正确用法 |
| :--- | :--- | :--- |
| 脚本报错 `must run inside a project container`（退出码 `2`） | 在宿主机直接运行了三端 `scripts/*.sh` | 先执行 `./env.sh <env>` 进入容器，或改用 `./env.sh exec <env> scripts/...` |
| 并行脚本报错 `并行入口/并行推理入口需要在宿主机执行`（退出码 `2`） | 在容器内运行了 `./record_parallel.sh` 或 `./inference_parallel.sh` | 退出容器，在宿主机项目根目录执行 |
| 区分 `--seed` 与 `--reset-seed` | `client_interactive.sh` / `backend.sh` 使用 `--seed`；`client_policy.sh` 透传 `runtime_node` 使用 `--reset-seed` | 交互式/后端用 `--seed <N>`；`client_policy.sh` 用 `--reset-seed <N>` |
| 区分 `--output-root` 与 `--output` | `client_interactive.sh` 接受 `--output-root`；`client_policy.sh` 接受 `--output` 或 `--episode-dir` | 见对应脚本参数表 |
| `convert.sh` 直接退出报错目标目录已存在 | 数据集转换有前置拒覆盖保护，避免耗尽读取校验才失败 | 先清理或移走旧目录，或使用 `--output-root` 指定新路径（失败未完成目录可加 `--replace`） |
| `./env.sh viewer` 启动报错无法连接 X11 | 桌面会话未授权当前用户的本地 X11 访问 | 在宿主机先执行 `xhost +SI:localuser:$(id -un)` |
| 本地 `50051` 端口已被占用导致 SSH 隧道转发失败 | 本地策略服务占用了 `127.0.0.1:50051` | 将 SSH 隧道转发至其他本地端口（如 `127.0.0.1:15051`），推理端追加 `--policy-endpoint 127.0.0.1:15051` |

## 天机硬件环境

```bash
./env.sh build hardware
./env.sh up hardware
./env.sh exec hardware scripts/check_config.sh
./env.sh hardware
```

硬件端按机器人组织在 `hardware/tianji/`，默认读取 `configs/devices.yaml`，包含现有控制器、夹爪与七路相机参数。设备库和 FFmpeg/V4L2 工具由镜像提供，USB、串口与相机节点由 Compose 挂载。配置检查只读取配置；Robot API 适配与设备执行调度参见 [硬件端说明](../../hardware/tianji/README.md)。
