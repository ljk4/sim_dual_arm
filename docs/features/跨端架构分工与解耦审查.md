# 跨端架构分工、通信契约与解耦架构说明

本文档系统梳理 `sim_dual_arm` 各运行端与公共层的职责边界、跨端通信与离线交接协议，以及经多轮收敛后的解耦状态与真机接入演进边界。

> **状态区分（文档内标注）**
> - **当前已落地实现**：`simulation` / `runtime` / `learning` 三容器网络与最小权限挂载隔离（`learning` 仅以 `/opt/policy-sdk:ro` 只读挂载 Policy SDK）；`shared/common` 与 `shared/scenarios/<robot>/<task>` 两级方案绑定与 `marvin_sim/profiles/` 公共档案复用；跨端公共原语（`robot_contracts` 统一路径四分区/严格 YAML/原子 JSON/标准 `RunContext`、`robot_ros_support.teacher_extension`）；统一硬件中性 `*_backend_time_ns` 与 `BackendInfo.control_grid_ns` 控制网格协商、`marvin_teacher_api_msgs` 统一 Teacher 扩展；宿主机 Docker 池收敛于 `shared/common/tools/host/`；`simulation/common/` 与 `tools/` 完全方案无关化、`marvin_sim/{stack,handover}` 平级对称且复用共通任务与自检底座；`learning` 按子包组织且实现自包含数据集与动态 Profile 维度适配。
> - **后续演进规划（真机接入 `hardware/`）**：`runtime` 中尚留存少量强绑定仿真复位/真值任务评估的采集前置（C2），待接入具体 `hardware/` 真机驱动与人工/感知任务判定入口时按 Robot API 扩展点对接。

## 1. 当前已落地架构：各端分工与跨端协作全貌

### 1.1 系统全景、容器挂载与网络隔离

仓库采用“三容器化运行端 + 真机接口边界 + 只读契约与方案层 + 宿主机编排层”拓扑：

```text
                    ┌─────────────────────────────────────────────────────┐
                    │ 宿主机编排层 (env.sh / record_parallel.sh /          │
                    │              inference_parallel.sh / X11 viewer)     │
                    └──────────────────────────┬──────────────────────────┘
                                               │ 管理容器生命周期、多路并发隔离与宿主机可视化
         ┌─────────────────────────────────────┼─────────────────────────────────────┐
         ▼                                     ▼                                     ▼
┌─────────────────────┐               ┌─────────────────────┐               ┌─────────────────────┐
│   simulation 容器    │               │    runtime 容器      │               │   learning 容器      │
│  (MuJoCo + EGL)     │◄─── ROS 2 ───►│  (ROS 2 + gRPC)     │◄─── gRPC ────►│ (PyTorch/LeRobot)   │
│  仅接入 [ros] 网段    │ (FastDDS UDP) │ 跨 [ros]+[learning] │ (Protobuf)    │ 仅接入 [learning] 网 │
│  含物理/渲染/Teacher  │               │  控制中枢/录制/导出   │  默认 :50051  │  100% ROS-free      │
└──────────┬──────────┘               └──────────┬──────────┘               └──────────┬──────────┘
           │ ▲                                   │ ▲                                   │ ▲
           │ │ 只读: /shared, /opt/ros-dev       │ │ 只读: /shared                      │ │ 只读: /shared, /third_party,
           │ │ 读写: /data                       │ │ 读写: /build, /data                │ │      /opt/policy-sdk
           ▼ │                                   ▼ │                                   ▼ │ 读写: /data
┌─────────────────────────────────────────────────────────────────────────────────────────────────┐
│ 共享资产与离线交接总线                                                                             │
│ • shared/      : 跨端契约(ROS IDL / Protobuf / JSON Schema)、共享 Python 库、两级方案与 host 编排│
│ • build/       : 由 runtime 构建的生成 SDK (ros-dev/ 供 sim+runtime；policy-sdk/ 供 runtime+learn)│
│ • var/         : 运行产物四分区 (/data/<robot>/<task>/{datasets, models, logs, debug})           │
│ • third_party/ : 离线受保护资产 (固定版 lerobot 源码 + resnet18 权重，仅只读挂给 learning)           │
└─────────────────────────────────────────────────────────────────────────────────────────────────┘
```

各运行端容器隔离边界由各自的 `docker-compose.yml` 与 `configs/container.env` 声明：

- **`simulation` 容器**（`simulation/mujoco/docker/docker-compose.yml`）：仅加入 `ros` 网络，绑定 NVIDIA GPU 与 EGL 离屏渲染（`MUJOCO_GL=egl`）；默认 `ROS_DOMAIN_ID=42`，采用 FastDDS UDP-only 配置（`shared/common/tools/docker/fastdds.xml`）；以只读挂载 `/app`、`/shared` 与 `/opt/ros-dev`（对应宿主机 `build/ros-dev/`），以读写挂载 `/data`（对应宿主机 `var/`）。
- **`runtime` 容器**（`runtime/ros2/docker/docker-compose.yml`）：同时加入 `ros` 与 `learning` 双网段，并注入 `host.docker.internal:host-gateway`（支持通过 SSH 隧道连接远端 GPU 上的策略服务），是唯一跨接 ROS 2 与 gRPC 的中枢；以只读挂载 `/app`、`/shared`，以读写挂载 `/build`（负责生成全部 SDK）与 `/data`。
- **`learning` 容器**（`learning/lerobot/docker/docker-compose.yml`）：仅加入 `learning` 网络，绑定 NVIDIA GPU，`PROJECT_USE_ROS=0`，强制 `HF_HUB_OFFLINE=1` / `HF_DATASETS_OFFLINE=1` / `TRANSFORMERS_OFFLINE=1`，与 ROS 彻底解耦；以只读挂载 `/app`、`/shared`、`/third_party` 与 `/opt/policy-sdk`（对应宿主机 `build/generated/policy-sdk/`，严格不挂载可写 `/build`），仅以读写挂载 `/data`。

### 1.2 各端职责分工边界

| 层级 / 运行端 | 核心职责（做什么） | 明确边界（不做什么） | 关键实现入口 |
| :--- | :--- | :--- | :--- |
| **`shared/common/`**<br>跨端公共层 | 定义全仓跨端契约：ROS 2 IDL（`robot_api_msgs`、`sim_api_msgs`）、Policy Protobuf（`policy.proto`）、JSON Schema（含导出与采集筛选契约）；提供 4 个公共 Python 包：`robot_contracts`（模型、`RunContext`、Profile、绑定、四分区路径、严格 YAML、原子 JSON 与 SHA-256）、`robot_ros_support`（ROS 消息编解码、QoS 与动态 Teacher 扩展加载）、`robot_run_logging`（结构化 JSONL 事件日志与公共 LogSettings）、`robot_trajectory`（受限样条轨迹生成、重定时与 C1/限位校验）；提供 SDK 构建、容器脚本、宿主机 `host/` Docker 池与绑定校验工具。 | 不选择具体机器人、任务或算法；不承载业务运行生命周期或物理仿真。 | `shared/common/interfaces/policy/policy.proto`、`shared/common/interfaces/ros/`、`shared/common/python/`、`shared/common/tools/host/` |
| **`shared/scenarios/<robot-id>/<task-id>/`**<br>方案绑定与配方层 | 按机器人与任务两级目录组织方案（`marvin_sim/stack`、`marvin_sim/handover`），并将跨任务共用的 Marvin 观测/动作/控制档案上提至 `marvin_sim/profiles/`、`marvin_teacher_api_msgs` 扩展收归 `marvin_sim/extensions/`，双任务按 `source_roots: [".."]` 平级对称引用。 | 不跨任务互指私有路径，不在 `binding.yaml` 中写死模型权重路径。 | `shared/scenarios/marvin_sim/stack/binding.yaml`、`shared/scenarios/marvin_sim/handover/binding.yaml` |
| **`simulation/mujoco/`**<br>物理仿真后端 | 1. **多线程并发模型**：ROS 节点 `BackendNode` 通过 `RosFutureBridge` 异步对接 worker；物理主线程 `_Owner` 独占活体 `MjData` 按 `physics.timestep` 步进物理；`RendererThread` 独立运行 EGL 离屏渲染并统计语义分割像素；`_Planner` 与 `_TaskPlanner` 分别处理 follower 准入与 Teacher 规划。<br>2. **轨迹安全准入与制动**：独立复核 Runtime 提交的轨迹，按本地时钟采样执行，并在 `BackendInfo` 宣布 `control_grid_ns`；制动模块复用 `robot_trajectory` 数学原语。<br>3. **通用底座与对称插件**：`common/` 与 `tools/probe_environment.py` 100% 方案无关，任务插件按 `(assembly, task_type)` 双键注册；机器人级代码位于 `marvin_sim/`，堆叠与交接插件/自检对称归于 `marvin_sim/{stack,handover}/`。<br>4. **就绪与旁路可视化**：就绪后写 `ready.json`；支持 `--namespace` 与 `--no-visualization` CLI 参数。 | 不直接连接 `learning` 容器；不写 MCAP 或训练数据集；`common/` 层不硬编码机器人或任务名。 | `simulation/mujoco/src/robot_backend_sim/common/ros/node.py`、`common/runtime/worker.py`、`common/tasks/registry.py`、`marvin_sim/` |
| **`runtime/ros2/`**<br>运行控制与录制中枢 | 1. **公共运行层**：校验后端能力、`Profile` 与 `BackendInfo.control_grid_ns`，管理租约与续租，按同序号配对 `ExactObservation`。<br>2. **统一流式轨迹调度**：Policy 与 Teacher 共用 `ContinuousStreamRunner` 完成预取/静止推进、重定时、受限多项式生成与幂等提交。<br>3. **在线与离线严格分层**：`episode_finalization.py` 等在线生命周期保留在包根；`offline/` 按 `collection/`、`export/`、`evaluation/`、`audit/` 四子包与 `parallel_common.py` 组织，离线指标统一消费 MCAP 与结构化导出产物，不爬取第三方运行文本日志。<br>4. **仿真运行层（`simulation/`）**：集中收归 `ResetSimulation`、任务状态解析与 Teacher 扩展调用。 | 不导入 `mujoco` 或 `mink`；在线业务严禁导入 `dual_arm_runtime.offline`；在线推理请求严禁传递物体真值或评价器状态。 | `runtime/ros2/ros/dual_arm_runtime/dual_arm_runtime/runtime_node.py`、`episode_runner.py`、`episode_finalization.py`、`offline/` |
| **`learning/lerobot/`**<br>训练与策略服务端 | 按 `dataset/`、`training/`、`serving/`、`adapters/` 四子包组织，100% ROS-free：<br>1. **数据转换（`dataset/`）**：校验 `formal-select.json` 与 `export/` 导出，写入含自包含筛选元数据的 `datasets/lerobot/`。<br>2. **模型训练（`training/`）**：结合 `third_party/` 离线资产，在内存读取 `datasets/lerobot/` 自包含元数据进行静止锚点过滤与训练（规则缺失即显式报错），输出 `models/act_<ts>/{model.safetensors, training_args.yaml}`。<br>3. **策略服务（`serving/` + `adapters/`）**：`PolicyServer` 基于 `RunContext` 与单写配置启动，直接以 `(C, H, W)` 零冗余转置流过 `ChunkedPolicyPipeline` 与适配器，维度/夹爪布局由 `RobotProfile` 动态派生。 | **100% ROS-free**，不读 MCAP 或 `datasets/raw/`，不爬取采集日志，不做热路径调试写盘。 | `learning/lerobot/src/dual_arm_learning/dataset/dataset.py`、`serving/server.py`、`serving/service.py`、`serving/pipeline.py`、`adapters/lerobot_act.py` |
| **`hardware/`**<br>真机硬件边界 | 定义真机接入接口契约（`*_backend_time_ns`、`BackendInfo.control_grid_ns`）与 Runtime 真机扩展对接方向。 | 当前仓库不包含任何真机驱动或假占位模块。 | `hardware/README.md` |
| **宿主机编排层** | `./env.sh` 管理容器生命周期与 X11 `viewer`；根目录 `./record_parallel.sh` 与 `./inference_parallel.sh` 调用 `shared/common/tools/host/` 中的标准库编排器管理隔离 `simulation` 容器并驱动 `runtime` 并发池，监听 `ready.json` 判断就绪并通过 CLI 传入仿真运行参数。 | 不在容器内嵌套 Docker（DinD）；不寄居 ROS 2 包内或跨端改写仿真 YAML 文件。 | `env.sh`、`record_parallel.sh`、`inference_parallel.sh`、`shared/common/tools/host/` |

### 1.3 跨端实时通信与离线交接契约

#### 1.3.1 实时通道一：`simulation` ↔ `runtime`（ROS 2 / FastDDS UDP）

默认命名空间为 `/robot`（并行 Worker 由编排层通过 `--namespace` 与 `ROS_DOMAIN_ID` 隔离），接口分为四层：

1. **核心机器人公共契约（`robot_api_msgs`，仿真与真机共用，时间戳统一 `*_backend_time_ns`）**：
   - **后端 → Runtime 发布 Topics**：
     - `info`（`BackendInfo`，`INFO_QOS`: Reliable + TransientLocal）：`RunContext`、就绪状态、标称控制执行周期 `control_grid_ns`、关节/相机列表及能力声明。
     - `state`（`RobotState`）：实测关节位置/速度与 `state_seq`。
     - `cameras/<name>/frame`（`CameraFrame`）：与 `state_seq` 严格同序号 `frame_seq` 的 `rgb8` 图像与相机内参/标定摘要。
     - `control_events`（`ControlEvent`）：命令与分块的生命周期事件（`ACCEPTED`、`STARTED`、`RETIRED`、`STOPPING`、`CANCELED`、`REJECTED` 等）。
     - `execution_feedback`（`ExecutionFeedback`）：参考/实测误差、跟踪质量、多爪手指力反馈及冻结终态。
     - `follower_references`（`FollowerReference`）：后端校验通过并实际生效的完整 `ReferenceSegment` 分段多项式系数与摘要。
   - **Runtime → 后端调用 Services**：
     - `acquire_control`、`renew_control`、`release_control`、`stop`：控制权租约管理与紧急制动。
     - `get_stream_anchor`、`submit_follower`、`query_stream_command`：交接锚点查询、分段轨迹提交通道与幂等查询。
   - **Runtime 自身发布/暴露（同步录入 MCAP）**：
     - Topics：`/runtime/status`（`RuntimeStatus`）、`/runtime/commands`（`StreamCommand`）、`/runtime/observation_index`（`ObservationIndex`）。
     - Services：`/runtime/episode/start`（`StartEpisode`）、`/runtime/episode/end`（`EndEpisode`）。
2. **仿真任务生命周期扩展（`sim_api_msgs`，仅仿真端启用）**：
   - Services：`/robot/reset_simulation`、`/robot/prepare_task`、`/robot/start_task`、`/robot/get_task_state`、`/robot/get_contact_snapshot`（含显式 `gripper_names`）。
   - Topic：`/robot/task_state`（`TaskState`）。
3. **方案专属 Teacher 扩展（`marvin_teacher_api_msgs`）**：
   - Service：`/robot/get_task_chunk`（能力标识 `marvin_teacher_api_msgs.teacher_chunk`，`marvin_sim` 各任务共用），返回相对当前观测时间的 `60×16 @ 50 ms` 示教目标块、阶段码及门控状态。
4. **MuJoCo 实时可视化旁路（仅 `simulation` 内部）**：
   - Topic：`/robot/visualization/mujoco_state`（`std_msgs/Float64MultiArray`），受 `--no-visualization` 控制。

#### 1.3.2 实时通道二：`runtime` ↔ `learning`（gRPC / Protobuf）

由 `shared/common/interfaces/policy/policy.proto` 定义 `bimanual.policy.PolicyService`（默认地址 `learning:50051`）：

- `GetPolicyInfo`、`OpenSession`（直接使用 `RunContext` 校验与单层配置）、`Predict`、`ResetSession`、`CloseSession`。

#### 1.3.3 跨端一致性守卫与产物交接

- **`RunContext` 七元组**：`robot_id`、`robot_profile_hash`、`backend_instance_id`、`time_domain_id`、`clock_epoch`、`episode_id`、`control_epoch`。
- **SDK 交接（`build/`）**：`runtime` 执行 `scripts/build_sdk.sh` 生成 `build/ros-dev/`（`simulation` 与 `runtime` 共用）与 `build/generated/policy-sdk/`（`learning` 以 `/opt/policy-sdk:ro` 只读挂载）。
- **四分区数据与模型交接（`var/<robot>/<task>/{datasets,models,logs,debug}`）**：各端统一使用 `robot_contracts.project_paths` 构建路径；`datasets/raw/` 与 `formal-select.json` 由结构化导出 Schema 约束；`datasets/lerobot/` 自包含训练与过滤所需的全部帧级/片段元数据；`models/act_<ts>/` 仅保存 `model.safetensors` 与备忘 `training_args.yaml`。

## 2. 架构解耦收敛状态与剩余演进边界

### 2.1 已完成收敛的跨端耦合与缺陷（Wave 1–5）

- **缺陷与热点消除（B1–B5）**：修复并行评估 `task_mode: inference` 参数、TTY 进度穿透、CLI 错误流与过时脚本重定向；取消热路径 `.npz` 同步写盘与配置重复三写；静止锚点过滤缺失 `gate_state` 时显式报错。
- **公共能力下沉与去重（D1–D6）**：`SHARED_ROOT`/绑定解析、四分区路径布局、严格 `read_unique_yaml`、规范哈希、原子写盘、`LogSettings`、`teacher_extension_modules` 与 `braking` 多项式/连续性校验全部收归 `shared/common/`；合并宿主机 `docker_pool` 与 `marvin_teacher_api_msgs`、抽离 `marvin_sim` 公共档案与任务/自检基类；清除无用导出列与冗余配置写入，统一使用 `RunContext` 契约与单一权威配置/报告。
- **职责归位与跨端契约对齐（M1–M5, C1, C3–C5）**：
  - 宿主机并行逻辑迁入 `shared/common/tools/host/` 并改为 CLI 传参（无跨端 YAML 改写）；
  - `simulation/common/` 与 `tools/probe_environment.py` 清除 Marvin/任务硬编码，支持 `(assembly, task_type)` 双键注册；
  - `marvin_sim/profiles/` 收纳公共档案，`source_roots` 收窄至 `..`；
  - `runtime` 在线代码与 `dual_arm_runtime.offline` 彻底单向依赖（在线禁导离线），结构化就绪采用 `ready.json`，移除跨端文本日志爬取；
  - `learning` 实现 `(C, H, W)` 零冗余转置、Profile 维度动态派生与自包含 `datasets/lerobot/`，容器挂载收窄为 `/opt/policy-sdk:ro`；
  - ROS IDL 与跨端字段统一重命名为 `*_backend_time_ns` 并新增 `BackendInfo.control_grid_ns`、`ContactSnapshot.gripper_names`，相机分辨率上限统一为 `4096`。

### 2.2 后续待演进边界（C2：真机运行时对接）

- `runtime/ros2` 的通用采集编排与部分导出质量判定当前仍对接 `simulation`、`sim_api_msgs`（复位与物体真值评估）及分割质量事件；待未来接入 `hardware/` 具体真机驱动时，按 Robot API 能力协商补齐真机采集选型、硬件复位/就绪钩子与非仿真质量验收通路。
