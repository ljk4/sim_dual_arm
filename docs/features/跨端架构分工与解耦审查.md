# 跨端架构分工、通信契约与解耦架构说明

本文档系统梳理 `sim_dual_arm` 各运行端、本体资产层与方案绑定层的职责边界、跨端通信与离线交接协议，以及四维正交解耦与未来扩展路线。

> **状态区分（文档内标注）**
> - **当前已落地实现**：`mujoco` / `runtime` / `lerobot` / `tianji` 命名容器与最小权限挂载隔离（`lerobot` 仅以 `/opt/policy-sdk:ro` 只读挂载 Policy SDK）；`shared/robots/<robot>/` 机器人公共资产上提；`shared/scenarios/<robot>/<backend>/<task>/` 与 `output/<robot>/<backend>/<task>/` 三层正交组织、`output/build/` 构建产物归并及 `RobotProfile.interface_digest`；跨端公共原语（`robot_contracts`、`robot_ros_support.teacher_extension`）；统一硬件中性 `*_backend_time_ns` 与 `BackendInfo.control_grid_ns` 控制网格协商；宿主机 Docker 池收敛于 `shared/common/tools/host/`；`simulation/mujoco` 插件按 `marvin/{stack,handover}` 对称组织；`learning/lerobot` 按子包组织且实现自包含数据集与动态 Profile 维度适配。
> - **后续演进规划**：真机 `hardware/tianji` ROS 2 与 Runtime 采集接入、新仿真器 `simulation/isaacsim`、强化学习范式及标定后的 Sim2Real，详见 [架构扩展与演进指南](架构扩展与演进指南.md)。

---

## 1. 当前已落地架构：各端分工与跨端协作全貌

### 1.1 系统全景、容器挂载与网络隔离

仓库采用“容器化运行端 + 只读公共层（公共契约、机器人本体资产、三层方案） + 统一 `output/` 离线交接 + 宿主机编排层”拓扑：

```text
                    ┌─────────────────────────────────────────────────────┐
                    │ 宿主机编排层 (env.sh / record_parallel.sh /          │
                    │              inference_parallel.sh / X11 viewer)     │
                    └──────────────────────────┬──────────────────────────┘
                                               │ 管理容器生命周期、多路并发隔离与宿主机可视化
         ┌─────────────────────────────────────┼─────────────────────────────────────┐
         ▼                                     ▼                                     ▼
┌─────────────────────┐               ┌─────────────────────┐               ┌─────────────────────┐
│     mujoco 容器      │               │    runtime 容器      │               │    lerobot 容器      │
│  (MuJoCo + EGL)     │◄─── ROS 2 ───►│  (ROS 2 + gRPC)     │◄─── gRPC ────►│ (PyTorch/LeRobot)   │
│  host 回环 UDPv4    │ (FastDDS UDP) │  host 回环中枢       │ (Protobuf)    │  host 回环 127.0.0.1 │
│  物理/渲染/Teacher   │  127.0.0.1    │  控制中枢/录制/导出   │  默认 :50051  │  100% ROS-free      │
└──────────┬──────────┘               └──────────┬──────────┘               └──────────┬──────────┘
           │ ▲                                   │ ▲                                   │ ▲
           │ │ 只读: /shared, /opt/ros-dev,      │ │ 只读: /shared                      │ │ 只读: /shared, /third_party,
           │ │      /data/build                  │ │ 读写: /build, /data                │ │      /opt/policy-sdk, /data/build
           │ │ 读写: /data                       ▼ │                                   ▼ │ 读写: /data
           ▼ │                                                                         │
┌─────────────────────────────────────────────────────────────────────────────────────────────────┐
│ 共享资产与离线交接总线                                                                             │
│ • shared/common/    : 跨端契约(ROS IDL / Protobuf / JSON Schema)、共享 Python 库、host 编排     │
│ • shared/robots/    : 机器人本体资产(URDF / meshes / 共享档案 / 扩展 ROS IDL)                    │
│ • shared/scenarios/ : 三层方案绑定 <robot>/<backend>/<task>/binding.yaml 与配方(SSOT)            │
│ • output/build/     : 由 runtime 构建的生成 SDK (ros-dev/ 与 generated/policy-sdk/)             │
│ • output/<r>/<b>/<t>/: 四分区运行产物 {datasets, models, logs, debug}                           │
│ • third_party/      : 离线受保护资产 (固定版 lerobot 源码 + resnet18 权重，只读挂给 lerobot)       │
└─────────────────────────────────────────────────────────────────────────────────────────────────┘
```

各运行端容器隔离边界由各自的 `docker-compose.yml` 与 `configs/container.env` 声明，统一采用 `network_mode: host` 并由配置约束为仅限本机回环（`127.0.0.1`）通信：

- **`mujoco` 容器**（`simulation/mujoco/docker/docker-compose.yml`）：采用 `network_mode: host`，绑定 NVIDIA GPU 与 EGL 离屏渲染（`MUJOCO_GL=egl`）；默认 `ROS_DOMAIN_ID=42`，采用限制在 `127.0.0.1` 回环接口的 FastDDS UDP-only 配置（`shared/common/tools/docker/fastdds.xml`）；以只读挂载 `/app`、`/shared`、`/opt/ros-dev`（`output/build/ros-dev/`）与 `/data/build`（`output/build/`），以读写挂载 `/data`（`output/`）。
- **`runtime` 容器**（`runtime/ros2/docker/docker-compose.yml`）：采用 `network_mode: host`，同时使用受 `fastdds.xml` 约束的 `127.0.0.1` 回环 ROS 2 与 `127.0.0.1:50051` gRPC（可直接对接本地 `lerobot` 或通过 SSH 本地转发连接远端 GPU 策略服务），是唯一跨接 ROS 2 与 gRPC 的中枢；以只读挂载 `/app`、`/shared`，以读写挂载 `/build`（`output/build/`，负责生成全部 SDK）与 `/data`（`output/`）。
- **`lerobot` 容器**（`learning/lerobot/docker/docker-compose.yml`）：采用 `network_mode: host`，策略服务默认绑定 `127.0.0.1:50051`，绑定 NVIDIA GPU，`PROJECT_USE_ROS=0`，强制 `HF_HUB_OFFLINE=1` / `HF_DATASETS_OFFLINE=1` / `TRANSFORMERS_OFFLINE=1`，与 ROS 彻底解耦；以只读挂载 `/app`、`/shared`、`/third_party`、`/opt/policy-sdk`（`output/build/generated/policy-sdk/`）与 `/data/build`（`output/build/`），仅以读写挂载 `/data`（`output/`）。
- **`tianji` 容器**（`hardware/tianji/docker/docker-compose.yml`）：采用 `network_mode: host`，挂载 `/dev`、`/sys`、`/run/udev` 与硬件配置文件，以只读挂载 `/app`、`/shared`、`/opt/ros-dev`、`/data/build`，以读写挂载 `/data`。

### 1.2 各端职责分工边界

| 层级 / 运行端 | 核心职责（做什么） | 明确边界（不做什么） | 关键实现入口 |
| :--- | :--- | :--- | :--- |
| **`shared/common/`**<br>跨端公共层 | 定义全仓跨端契约：ROS 2 IDL（`robot_api_msgs`、`sim_api_msgs`）、Policy Protobuf（`policy.proto`）、JSON Schema；提供 4 个公共 Python 包：`robot_contracts`（模型、`RunContext`、Profile、`interface_digest`、三层绑定、输出路径、严格 YAML、原子 JSON 与 SHA-256）、`robot_ros_support`、`robot_run_logging`、`robot_trajectory`；提供 SDK 构建、容器脚本、宿主机 `host/` Docker 池与绑定校验工具。 | 不选择具体机器人、后端、任务或算法；不承载业务运行生命周期或物理仿真。 | `shared/common/interfaces/policy/policy.proto`、`shared/common/interfaces/ros/`、`shared/common/python/`、`shared/common/tools/host/` |
| **`shared/robots/<robot-id>/`**<br>机器人本体公共资产层 | 存放跨后端、跨任务复用的原始 URDF、STL 网格、共享观测/动作/控制档案以及机器人级 ROS 扩展（如 `shared/robots/marvin/` 及其 `marvin_teacher_api_msgs`）。 | 不包含特定仿真引擎或特定任务的数值配方。 | `shared/robots/marvin/README.md` |
| **`shared/scenarios/<robot>/<backend>/<task>/`**<br>三层方案绑定层 | 按机器人、执行后端、任务三层目录组织方案（`marvin/mujoco/stack`、`marvin/mujoco/handover`），通过 `source_roots: ["../../../../robots/marvin"]` 复用机器人公共资产并持有任务级 `RobotProfile` 与配方。 | 不跨任务互指私有路径，不在 `binding.yaml` 中写死模型权重路径。 | `shared/scenarios/marvin/mujoco/stack/binding.yaml`、`shared/scenarios/marvin/mujoco/handover/binding.yaml` |
| **`simulation/mujoco/`**<br>物理仿真后端 | 1. **多线程并发模型**：ROS 节点 `BackendNode` 通过 `RosFutureBridge` 异步对接 worker；物理主线程独占活体 `MjData` 步进物理；`RendererThread` 独立运行 EGL 离屏渲染；`_Planner` 与 `_TaskPlanner` 分别处理 follower 准入与 Teacher 规划。<br>2. **轨迹安全准入与制动**：独立复核 Runtime 提交的轨迹并按本地时钟采样执行，在 `BackendInfo` 宣布 `control_grid_ns`。<br>3. **通用底座与对称插件**：`common/` 与 `tools/probe_environment.py` 100% 方案无关，资产从 `shared/robots/` 动态加载，插件目录对称组织于 `marvin/{stack,handover}/`。<br>4. **就绪与旁路可视化**：就绪后写 `ready.json`；支持 `--namespace` 与 `--no-visualization` CLI 参数。 | 不直接连接 `lerobot` 容器；不写 MCAP 或训练数据集；`common/` 层不硬编码机器人或任务名。 | `simulation/mujoco/src/robot_backend_sim/common/ros/node.py`、`common/runtime/worker.py`、`common/tasks/registry.py`、`marvin/` |
| **`runtime/ros2/`**<br>运行控制与录制中枢 | 1. **公共运行层**：校验后端能力、`Profile` 与 `BackendInfo.control_grid_ns`，管理租约与续租，按同序号配对 `ExactObservation`。<br>2. **统一流式轨迹调度**：Policy 与 Teacher 共用 `ContinuousStreamRunner` 完成预取/静止推进、重定时、受限多项式生成与幂等提交。<br>3. **在线与离线严格分层**：`episode_finalization.py` 等在线生命周期保留在包根；`offline/` 按 `collection/`、`export/`、`evaluation/`、`audit/` 与 `parallel_common.py` 组织，离线指标统一消费 MCAP 与结构化导出产物。<br>4. **仿真运行层（`simulation/`）**：集中收归 `ResetSimulation`、任务状态解析与 Teacher 扩展调用。 | 不导入 `mujoco` 或 `mink`；在线业务严禁导入 `dual_arm_runtime.offline`；在线推理请求严禁传递物体真值或评价器状态。 | `runtime/ros2/ros/dual_arm_runtime/dual_arm_runtime/runtime_node.py`、`episode_runner.py`、`episode_finalization.py`、`offline/` |
| **`learning/lerobot/`**<br>训练与策略服务端 | 按 `dataset/`、`training/`、`serving/`、`adapters/` 四子包组织，100% ROS-free：<br>1. **数据转换（`dataset/`）**：校验 `formal-select.json` 与 `export/` 导出，写入含自包含筛选元数据的 `datasets/lerobot/`。<br>2. **模型训练（`training/`）**：结合 `third_party/` 离线资产，在内存读取自包含元数据进行静止锚点过滤与训练，输出 `models/act_<ts>/{model.safetensors, training_args.yaml}`。<br>3. **策略服务（`serving/` + `adapters/`）**：`PolicyServer` 基于 `RunContext` 与单写配置启动，直接以 `(C, H, W)` 零冗余转置流过 `ChunkedPolicyPipeline` 与适配器，维度/夹爪布局由 `RobotProfile` 动态派生。 | **100% ROS-free**，不读 MCAP 或 `datasets/raw/`，不爬取采集日志，不做热路径调试写盘。 | `learning/lerobot/src/dual_arm_learning/dataset/dataset.py`、`serving/server.py`、`serving/service.py`、`serving/pipeline.py`、`adapters/lerobot_act.py` |
| **`hardware/tianji/`**<br>天机硬件端 | 提供 APEX 双臂、90C 夹爪、RealSense 与视触觉驱动、设备配置和 `tianji` Docker 环境。 | Robot API、轨迹执行调度与 Runtime 联通按扩展指南逐步接入。 | `hardware/tianji/README.md`、`hardware/tianji/src/robot_backend_hardware/` |
| **宿主机编排层** | `./env.sh` 管理容器生命周期与 X11 `viewer`；根目录 `./record_parallel.sh` 与 `./inference_parallel.sh` 调用 `shared/common/tools/host/` 中的编排器管理隔离 `simulation/<backend>` 容器并驱动 `runtime` 并发池，监听 `ready.json` 并通过 CLI 传入 `--robot/--backend/--task`。 | 不在容器内嵌套 Docker（DinD）；不跨端改写仿真 YAML 文件。 | `env.sh`、`record_parallel.sh`、`inference_parallel.sh`、`shared/common/tools/host/` |

### 1.3 跨端实时通信与离线交接契约

#### 1.3.1 实时通道一：`mujoco` / `hardware` ↔ `runtime`（ROS 2 / FastDDS UDP）

默认命名空间为 `/robot`（并行 Worker 由编排层通过 `--namespace` 与 `ROS_DOMAIN_ID` 隔离），接口分为四层：

1. **核心机器人公共契约（`robot_api_msgs`，仿真与真机共用，时间戳统一 `*_backend_time_ns`）**：
   - **后端 → Runtime 发布 Topics**：
     - `info`（`BackendInfo`，`INFO_QOS`: Reliable + TransientLocal）：`RunContext`、就绪状态、标称控制执行周期 `control_grid_ns`、关节/相机列表及能力声明。
     - `state`（`RobotState`）：实测关节位置/速度与 `state_seq`。
     - `cameras/<name>/frame`（`CameraFrame`）：与 `state_seq` 严格同序号 `frame_seq` 的 `rgb8` 图像与相机内参/标定摘要。
     - `control_events`（`ControlEvent`）：命令与分块的生命周期事件（`ACCEPTED`、`STARTED`、`RETIRED`、`STOPPING`、`CANCELED`、`REJECTED` 等）。
     - `execution_feedback`（`ExecutionFeedback`）：参考/实测误差、跟踪质量、多爪手指力反馈及冻结终态。
     - `follower_references`（`FollowerReference`）：后端校验通过并实际生效的完整 `ReferenceSegment` 分段多项式系数与摘要。
   - **Runtime → 后端调用 Services**：
     - `acquire_control`、`renew_control`、`release_control`、`stop`：控制权租约管理与紧急制动。
     - `get_stream_anchor`、`submit_follower`、`query_stream_command`：交接锚点查询、分段轨迹提交通道与幂等查询。
   - **Runtime 自身发布（同步录入 MCAP）**：
     - Topics：`/runtime/commands`（`StreamCommand`）、`/runtime/observation_index`（`ObservationIndex`）。
2. **仿真任务生命周期扩展（`sim_api_msgs`，仅仿真端启用）**：
   - Services：`/robot/reset_simulation`、`/robot/prepare_task`、`/robot/start_task`、`/robot/get_task_state`。
   - Topic：`/robot/task_state`（`TaskState`）。
3. **机器人/方案专属 Teacher 扩展（`marvin_teacher_api_msgs`）**：
   - Service：`/robot/get_task_chunk`（能力标识 `marvin_teacher_api_msgs.teacher_chunk`，由 `shared/robots/marvin/` 提供，Marvin 各任务共用），返回相对当前观测时间的 `60×16 @ 50 ms` 示教目标块、阶段码及门控状态。
4. **MuJoCo 实时可视化旁路（仅 `simulation/mujoco` 内部）**：
   - Topic：`/robot/visualization/mujoco_state`（`std_msgs/Float64MultiArray`），受 `--no-visualization` 控制。

#### 1.3.2 实时通道二：`runtime` ↔ `lerobot`（gRPC / Protobuf）

由 `shared/common/interfaces/policy/policy.proto` 定义 `bimanual.policy.PolicyService`（默认地址 `127.0.0.1:50051`）：

- `GetPolicyInfo`、`OpenSession`（直接使用 `RunContext` 校验与单层配置）、`Predict`、`ResetSession`、`CloseSession`。

#### 1.3.3 跨端一致性守卫与产物交接

- **`RunContext` 七元组**：`robot_id`、`robot_profile_hash`、`backend_instance_id`、`time_domain_id`、`clock_epoch`、`episode_id`、`control_epoch`。
- **SDK 交接（`output/build/`）**：`runtime` 执行 `scripts/build_sdk.sh` 生成 `output/build/ros-dev/`（`mujoco`、`tianji` 与 `runtime` 共用）与 `output/build/generated/policy-sdk/`（`lerobot` 以 `/opt/policy-sdk:ro` 只读挂载）。
- **四分区数据与模型交接（`output/<robot>/<backend>/<task>/{datasets,models,logs,debug}`）**：各端统一使用 `robot_contracts.project_paths` 构建路径；`datasets/raw/` 与 `formal-select.json` 由结构化导出 Schema 约束；`datasets/lerobot/` 自包含训练与过滤所需的全部帧级/片段元数据；`models/act_<ts>/` 仅保存 `model.safetensors` 与备忘 `training_args.yaml`。
