# 异步流式推理、延迟匹配与时序不变静止推进

本文档定义策略闭环流式执行（`PolicyStreamRunner`）的后台异步推理、UMI 风格延迟匹配、启动预热与时序不变静止推进机制。

> **状态区分（文档内标注）**
> - **本轮已落地**：独立后台生产者线程（两阶段推测预取 + 交接前新鲜推理 + 阻塞降级防 `CHUNK_LATE`）、UMI 风格延迟匹配（`ActionWindow` 自动剔除推理/预取过期步 + 可配置 `action_execution_latency_ns` 剔除执行滞后步）、绝对时间戳历史缓存环（`_CachedPrediction`、`deque(maxlen=12)`、净位移静止判据、时序不变 + 新值优先整窗回退）、以及启动稳定等待与全链路预热（`startup_settle_sim_ns` + `warmup_on_settle` + `OpenSession` warm-up）。
> - **后续期望落地**：更短执行窗（`0.25–0.5 s`）动态重规划评估、支持多帧历史观测（`n_obs_steps >= 2`）与状态化策略服务会话队列。

---

## 1. 功能定位与核心不变量

- **所属层**：通用运行端（`runtime/ros2/ros/dual_arm_runtime/dual_arm_runtime/chunk_stream.py`、`runtime_config.py`）与跨端窗口契约（`shared/common/python/contracts/src/robot_contracts/action_chunks.py`），100% 机器人/任务无关。
- **核心设计不变量**：
  1. **时序不能变（Timeline Invariance）**：任何预测点的绝对仿真时间戳 `t_abs = t_obs + (i + 1) * action_period_ns` 严禁被前移或改写；静止推进仅允许在后续窗口落入静态前缀时，按**完全一致的绝对时间戳**复用历史预测。
  2. **新值优先（Newest-Observation Priority）**：只要最新预测在目标执行窗内存在有效净推进（锚点基准到窗口终点位移达到阈值），一律整窗采用最新预测；单窗内不做跨块拼接。
  3. **延迟匹配（Latency Matching）**：严格扣除推理/传输/预取耗时与可选执行器滞后对应的首部预测步，确保物理到位时刻与模型预测时刻对齐，避免跨块跳变。
  4. **最小必要机制（去模型耦合）**：运行端不保留与特定策略分布耦合的时间扭曲补丁，仅保留通信与物理安全底线（ACK、控制租约、Ruckig 插值/限位/平滑、协同轴组可达包络重定时、启动预热与按轴微幅硬限位投影）。

## 2. 本轮已落地实现

### 2.1 启动稳定等待与全链路预热
- **服务端预热（`learning`）**：`OpenSession` 阶段执行模型适配器 `warm_up`，触发 CUDA kernel 编译与显存池初始化。
- **运行端首帧预热（`runtime`）**：在 `StartTask` 计入任务预算之前执行 `_startup_settle()`：
  - 等待仿真时钟流逝 `policy.startup_settle_sim_ns`（范围 `0 .. 15 s`，双方案默认 `3.0 s`）；
  - 当 `policy.warmup_on_settle: true` 时，使用首帧真实观测发起一次 `Predict` + `Reset` RPC，使正式首块推理稳定在 `21–30 ms`；
  - 记录 `policy.startup_settle.started` 与 `policy.startup_settle.completed` 结构化事件。

### 2.2 后台真正异步推理与两阶段预取
当 `policy.async_inference: true`（默认启用）时，`PolicyStreamRunner` 启动独立后台生产者线程 `policy-async-producer`，与主提交循环并行运行：

```text
观测流 obs(t) ──▶ [后台生产者线程 policy-async-producer]
                     ├── 阶段 1（推测备份）：obs 到达 H_k - min(2 * prefetch_lead_ns, 450 ms) 时执行 1 次后台 Predict 并写入历史环
                     └── 阶段 2（新鲜目标）：obs 到达 H_k - prefetch_lead_ns 时执行新鲜 Predict 并唤醒主循环
                                    │
                                    ▼
主循环 Consumer ──▶ get_anchor() 获取固定交接锚点 H_k
               ──▶ 正常取阶段 2 新鲜预测；若目标 RPC 阻塞至 robot_time_ns >= H_k - fallback_margin_ns，
                   立即降级取阶段 1 已完成的推测备份（fallback_margin_ns = clamp(prefetch_lead_ns // 2, 50ms, 100ms)）
               ──▶ _prepare_window()：延迟匹配 → 新值优先 / 时序不变静止回退
               ──▶ retime_action_window()（可达包络与协同轴组重定时）──▶ submit_follower + ACK
```

- 生产者线程串行调用 `source.predict`，保证同一 gRPC 会话无并发冲突；同时与主线程的 ROS 发布、`submit_follower`、锚点查询与任务终态轮询完全并行。
- 当 `prefetch_lead_ns == 0` 时退化为每块单观测后台异步推理；退出时由 `_close_runner()` 安全唤醒并回收线程，异常（含 `TaskTerminal` / `ContractError`）完整传回主线程。

### 2.3 UMI 风格延迟匹配（Latency Matching）
- **推理/传输/预取延迟匹配**：`ActionWindow._selection()` 按 `observation_time_ns + target.time_ns > handoff_time_ns` 自动丢弃首部 `inference_skipped_steps = window.skipped_overlap_count` 个已过期动作步。
- **动作执行滞后匹配**：`PolicyConfig` 提供 `action_execution_latency_ns`（默认 `0`，上限 `500 ms`，两方案配方显式声明并支持 `--set` 覆盖）：
  - 计算 `exec_steps = round(action_execution_latency_ns / action_period_ns)`；
  - 当 `exec_steps > 0` 时，`_apply_execution_latency()` 在推理过期步之上额外丢弃前 `exec_steps` 个预测步（并校验剩余预测视野足够覆盖 `target_count`），发送对齐后的目标并上报 `policy.latency_matched` 事件（含 `inference_latency_ns`、`execution_latency_ns`、`inference_skipped_steps`、`execution_skipped_steps`、`total_skipped_steps`）。

### 2.4 历史预测缓存与时序不变静止推进
- **缓存结构**：`_CachedPrediction(observation_id, stamp_ns, by_abs_time_ns)` 存入有界环 `self._prediction_history: deque(maxlen=12)`，保留最近 12 次已通过契约校验的原始预测（不修改任何时间戳）。
- **窗口净推进判据（`_has_window_progress`）**：仅比较**锚点基准 `anchor.reference.positions` 到选中窗口终点 `selected[-1].positions` 的净位移**（忽略窗口初段微小回弹抖动）：
  - 线性轴（`joint.unit == "m"`）：`>= 0.003 m`；
  - 旋转轴（`joint.unit != "m"`）：`>= 0.030 rad`。
- **整窗原子回退规则（`_prepare_window`）**：
  1. 若最新预测在选中窗口内存在有效净推进 → **整窗直接使用最新预测（新值优先）**；
  2. 否则计算选中窗口对应的目标绝对时间戳 `required_abs_times`（含执行延迟偏移 `exec_offset_ns`），从新到旧检索 `_prediction_history` 中第一个完整覆盖 `required_abs_times` 且满足净推进阈值的历史预测；
  3. 命中时，按精确 `t_abs` 填入窗口目标点，仍锚定当前新鲜 `observation_id / observation_time_ns` 提交后端以维持 `max_observation_age_s` 活性校验，并记录 `policy.wait_advance_applied` 事件（字段：`chunk_index`、`observation_id`、`source_observation_id`、`source_stamp_ns`、`handoff_sim_time_ns`）；
  4. 若全部历史预测在该窗口内均无净推进，则保持最新预测的静止输出。

### 2.5 保留与停用的推理机制边界

| 类别 | 机制 | 归属 | 定位 |
| :--- | :--- | :--- | :--- |
| **保留** | ACK 应答、控制租约、幂等查询 | `runtime` / `simulation` | 通信可靠性与单写者控制权底线 |
| **保留** | Ruckig 插值、速度/加速度/硬限位与可刹停检查 | `simulation/common` | 物理安全执行底线 |
| **保留** | 可达包络与同臂协同轴组等比例重定时 | `shared/common` | 运动学物理可达性约束（详见 [多轴协同过渡重定时](多轴协同过渡重定时.md)） |
| **保留** | 启动稳定等待与全链路预热 | `runtime` / `learning` | 消除首帧 CUDA JIT 延迟尖峰 |
| **保留** | 按轴微幅硬限位投影（`max_prediction_corrections`） | `learning` | 裁剪模型线性输出头在硬限位边缘的微小过冲 |
| **停用** | `TemporalEnsemble`（时间融合） | `learning` | `temporal_ensemble_coeff: null`，避免历史加权拖慢实时响应 |

## 4. 后续期望落地

1. **数据源头去空等后的更短提前量**：当 Teacher 采集侧压缩航点间无用空等后，可将 `prefetch_lead_ns` 进一步收缩至 `100–150 ms`。
2. **多帧/状态化策略流式协议扩展**：当策略输入升级为 `n_obs_steps >= 2` 或维护服务端隐状态时，后台生产者按观测序维护会话输入队列。
3. **短执行窗自适应评估**：结合真实执行器滞后标定，评估 `0.25–0.5 s` 执行窗与异步流水线的闭环响应收益。
