# 架构扩展与演进指南

本文面向需要在本仓库中**接入真机硬件、扩展新仿真后端、引入新学习范式（如强化学习 RL）或开展 Sim2Sim / Sim2Real** 的开发者，说明当前系统的正交扩展边界、已预留的契约钩子，以及后续工程实施的关键约束与推荐路径。

---

## 1. 四维正交解耦架构与目录布局

系统按 **机器人本体（Robot） × 执行后端（Backend） × 运行编排（Runtime） × 学习范式（Learning）** 四个正交维度解耦：

1. **机器人本体公共资产（`shared/robots/<robot-id>/`）**：
   - 存放与具体后端、具体任务无关的机器人 URDF、网格、共享观测/动作/控制档案以及机器人共享扩展接口（如 `shared/robots/marvin/`）。
2. **三层方案绑定（`shared/scenarios/<robot-id>/<backend-id>/<task-id>/`）**：
   - 按 `机器人 / 执行后端 / 任务` 三层目录组织 `binding.yaml` 与配方，例如 `shared/scenarios/marvin/mujoco/stack/`、`shared/scenarios/marvin/mujoco/handover/`。
   - 所有端入口统一使用 `--robot <robot-id> --backend <backend-id> --task <task-id>`（或直指配方的 `--config`）。
3. **统一输出目录（`output/`）**：
   - `output/build/`：存放运行端生成的跨端 SDK（`output/build/ros-dev/` 与 `output/build/generated/policy-sdk/`）。
   - `output/<robot-id>/<backend-id>/<task-id>/{datasets,models,logs,debug}/`：各方案的数据、模型、日志与诊断产物按三层坐标严格隔离；`_direct/` 与 `_system/` 为系统保留前缀，`build` 为 `robot-id` 保留词（`RESERVED_ROBOT_SEGMENTS`）。
4. **容器环境命名（`./env.sh`）**：
   - 保留 `runtime` 作为实时控制与采集编排中枢语义名；其余执行端与学习端容器采用**具体方案名**（当前为 `mujoco`、`lerobot`、`tianji`），后续新增后端或学习端直接以新方案名注册（如 `isaacsim`、`rl`），不占用泛化顶层名。

```text
shared/robots/<robot>/          # 机器人本体资产与共享契约（URDF / meshes / 共享 profiles / 扩展 IDL）
shared/scenarios/<robot>/<backend>/<task>/
                                # 三层方案绑定与参数配方（SSOT）
simulation/<sim>/ | hardware/<hw>/
                                # 执行后端：实现 robot_api_msgs（仿真附加 sim_api_msgs）
runtime/ros2/                   # 实时运行中枢：生命周期、录制导出、流式控制、SDK 构建
learning/<framework>/           # 离线与服务端学习端（ROS-free）：convert / train / gRPC PolicyService
output/build/                   # 跨端生成的 ROS 2 接口与 Policy SDK
output/<robot>/<backend>/<task>/
                                # 三层隔离的数据集、模型、日志与诊断产物
```

## 2. 真机硬件接入指南（`hardware/tianji` 与未来新真机）

### 2.1 `hardware/tianji` 接入位置与职责边界

`hardware/tianji/` 已完成天机 APEX 双臂驱动（`robot_backend_hardware.tianji.arms.ApexRobotActuator`）、大寰 90C 夹爪（`grippers/changingtek_90c.py`）、RealSense 与视触觉相机队列对齐采集以及 `./env.sh up tianji` 容器环境基础建设；后续对接闭环只需聚焦以下四处：

1. **复用的安全控制核心**：
   - 将 `simulation/mujoco` 控制层中纯 Python 实现的轨迹连续性检查、局部拼接覆盖与可刹停包络验证（`braking`）上提至公共包 `shared/common/python/trajectory/`，使真机后端仅专注硬件伺服而不重复实现平滑护栏。
2. **ROS 2 后端接口适配（实现 `robot_api_msgs`，不依赖 `sim_api_msgs`）**：
   - 在 `hardware/tianji` 启动 ROS 2 节点，订阅 `FollowCommand` / `ControlCommand`，发布 `Observation` 与 `BackendInfo`。
   - **伺服网格与单位转换**：通过 `BackendInfo.control_grid_ns` 声明真机实际伺服周期（例如 `10_000_000` ns / `100 Hz`），后端内部完成公共协议标准单位（`rad`、`m`）到天机 SDK 单位（`deg`、`mm`）的转换。
   - **CSP 硬护栏与安全停机（必须严守）**：
     - 真机底层 `ApexRobotActuator` 受 `max_joint_step_deg`（默认 `1.0°`）限制，单周期关节指令超步会触发跟随误差故障 `0xFF73`；任何上层轨迹重定时或流式补帧下发到天机前均不可越界。
     - 停止或模式切换必须走 `_stop_tracking(wait=...)` 先清跟踪标志再排空状态，避免触发状态机故障 `0xE001`。
3. **多相机与状态同步对齐**：
   - 复用 `hardware/tianji/src/robot_backend_hardware/common/camera/capture.py` 的 `seq` 对齐通道采集 3 路主 RGB 相机（`cam_high`、`cam_left_wrist`、`cam_right_wrist`），启动时基于 RealSense 出厂内参预计算 `cv2.initUndistortRectifyMap`，每帧通过单次 `cv2.remap` 完成去畸变、主点居中 `(160.0, 120.0)` 与 `320×240` 下采样，统一打上单调后端时间戳与 `calibration_digest` 发布 `Observation`；4 路视触觉相机按 `devices.yaml` 可选开关独立记录，阶段一不进入主公共观测契约。
4. **运行端能力协商（`runtime/ros2`）与真机采集入口**：
   - 运行端依据 `BackendInfo.capabilities` 区分仿真与真机：仿真后端提供 `sim_api_msgs` 物体真值 reset/evaluate；真机后端下，优先在 `dual_arm_runtime` 落地跨仿真/真机通用的**单手柄微分 IK + 零空间肘部保持遥操源**（接入 `TargetSource`，支持按键复位确认与人工成功/废弃打标），并在采集架构中预留实验室现有“边拖边录 + 脚踏板数字输入控制”采集程序的产物导入适配接口。

### 2.2 新增其他真机平台

若未来引入其他双臂或单臂真机（如 `hardware/<new_hw>/`）：
1. 在 `shared/robots/<new_robot>/` 放置新机器人 URDF、网格与 `profiles/`。
2. 新建 `hardware/<new_hw>/`，实现对应厂商 SDK 适配，并复用共享控制核心暴露 `robot_api_msgs`。
3. 在根 [`env.sh`](../../env.sh) 注册 `<new_hw>` 容器入口，并在 `shared/scenarios/<new_robot>/<new_hw>/<task>/binding.yaml` 中绑定 `backend.kind: hardware`、`backend.implementation: <new_hw>`。

## 3. 新仿真后端扩展指南（以 `simulation/isaacsim` 为例）

当需要引入 GPU 物理/光线追踪仿真器（如 Isaac Sim / Isaac Lab）时，按以下方式保持正交隔离：

1. **目录与容器**：
   - 新建 `simulation/isaacsim/`（独立 Dockerfile、Compose、适配源码），在 [`env.sh`](../../env.sh) 中注册 `isaacsim` 环境名。
   - 方案绑定建于 `shared/scenarios/marvin/isaacsim/<task>/`，产物自动归入 `output/marvin/isaacsim/<task>/`，与 `mujoco` 完全平行。
2. **复用本体资产（SSOT）**：
   - 严禁向 `shared/robots/marvin/` 塞入未维护的多份手工副本；`simulation/isaacsim` 直接读取 `shared/robots/marvin/urdf/` 与 `meshes/`，在容器构建或启动缓存中转换为 USD（生成物放容器缓存或 `output/build/isaacsim/`），并核对光学相机坐标系（OpenCV `+Z` 前视 vs OpenGL `-Z` 前视）与关节阻尼/刚度映射。
3. **双模式运行定位**：
   - **高保真闭环评测 / 单局可视化采集**：实现 ROS 2 `robot_api_msgs` + `sim_api_msgs`，直接复用整套 `runtime/ros2`、`learning` gRPC Policy 服务及 `./inference_parallel.sh --robot marvin --backend isaacsim --task <task>`。
   - **大规模并行训练（GPU Vectorized Envs）**：不经 ROS 2 DDS 与磁盘 MCAP，直接在仿真/学习耦合容器内通过 GPU Tensor 缓冲区直连环境步进。

## 4. 新学习范式扩展指南（强化学习 RL 与扩展 VLA）

当前 `learning/lerobot/` 以 ROS-free 的离线转换 + 模仿学习（ACT）服务为核心；后续引入独立强化学习端 `learning/rl/`（基于 `TorchRL` + `TensorDict`，重点依托 Google Colab 大内存进程内高并发环境运行），同时承担**与 ACT 平级的独立策略、ACT 宏步残差后训练器及特权 RL 示教器**三重职责，详细架构与 Real2Sim 预留接口规范见 [强化学习架构与 Real2Sim 协同设计](强化学习架构与Real2Sim协同设计.md)：

1. **公共策略服务与多范式方案绑定**：
   - 将当前 `PolicyService` 与 `PolicyModelAdapter` 上提至 `shared/common/python/policy_serving/`，供 `lerobot`（ACT）、`rl` 及未来自定义 VLA 共用同一 gRPC 推理服务与逐轴安全准入；`binding.yaml` 升级为按范式命名的多槽位字典（`learning.act`、`learning.rl` 等），产物统一按 `<范式前缀>_<YYYYMMDD_HHMMSS>/` 归入 `models/`。
2. **跨端契约不变下的双轨动作与非对称观测**：
   - 跨端 [`policy.proto`](../../shared/common/interfaces/policy/policy.proto) 保持 16 维 `joint_position` 动作块不变，部署态 Actor 输入对齐真机与仿真的 3 路下采样 RGB + 16 维关节状态；训练期 Critic 与特权 RL 示教直接读取 `TaskObservation` 物理真值，内部支持末端笛卡尔增量（经内置 `mink` IK 转为平滑关节块）与 ACT 残差增量双轨输出。
3. **统一无损数据集格式（兼容 ACT / RL / 外部 VLA）**：
   - 扩展版 LeRobot Parquet 分片支持内嵌无损 PNG 字节列，并补齐双臂末端 EE 6D 位姿、`task` 文本与 `reward` / `done` 字段；既供 `learning/lerobot` 与 `learning/rl` 直接消费，也可通过 `pyarrow` 无损转换为任意外部自定义 VLA 格式。

## 5. Sim2Sim 与 Sim2Real 演进路线（Marvin 仿真 vs 天机真机现状）

### 5.1 当前已知物理与硬件差异（现阶段暂不开展 Sim2Real）

`simulation/mujoco` 中的 `marvin` 是天机真机的基础机械臂运动学与动力学校准前模型，但**现阶段与实验室天机真机存在两项明确差异**，暂不直接做跨端模型迁移：

1. **末端夹爪与腕部感知硬件不同**：真机双臂末端安装的是实验室的大寰 90C 夹爪、手腕 RealSense 相机与 4 路视触觉传感器；机械尺寸、质量分布、夹持包络与腕部相机安装位姿/内参均与当前 MuJoCo 模型中的原装末端不符。
2. **物理尺寸与外参尚未标定**：真机双臂基座相对安装位姿、工作桌面高度、物体初始分布以及全局/手腕相机的手眼标定（Extrinsics / Intrinsics）尚未完成实测校准。

### 5.2 契约级预留机制（已落地）

虽然当前不直接执行 Sim2Real 迁移，架构已在数据契约与目录层级上完成防误用隔离与接口对齐准备：

1. **独立实体 `RobotProfile` + 严格产物隔离**：
   - 仿真后端使用 `shared/scenarios/marvin/mujoco/<task>/profiles/robot/profile.json`，未来真机使用 `shared/scenarios/marvin/tianji/<task>/profiles/robot/profile.json`；各自记录真实的 `initial` 状态、`calibration_digest` 与相机列表，模型与数据集默认隔离在各自的 `output/marvin/<backend>/<task>/`。
2. **`RobotProfile.interface_digest` 契约预校验**：
   - [`models.py`](../../shared/common/python/contracts/src/robot_contracts/models.py) 中的 `RobotProfile.interface_digest` 对关节名、顺序、夹爪定义及相机拓扑计算稳定摘要，刻意排除 `profile_id`、`initial` 与 `calibration_digest` —— 当两端仅标定参数或初始姿态不同但控制拓扑一致时，`interface_digest` 保持一致，便于未来在转换/迁移层显式开启受控跨端复用，而非默认混用未标定权重。

### 5.3 后续开启 Sim2Real 实施清单（天机 Real2Sim 对齐路线）

完整方案与待确认硬件清单见 [天机 Real2Sim 标定与实施方案](天机Real2Sim标定与实施方案.md)，核心实施步骤如下：

1. **原地升级 `marvin` 本体与几何建模**：确认实验室末端 CAD 与指垫实测尺寸后，原地重构 `shared/robots/marvin/` 与 `simulation/mujoco` 装配（碰撞体采用实测解析几何，视觉层支持挂载可选 STL 网格，并统一暴露语义句柄 `tcp_site_ids`、`finger_pad_body_ids`、`pad_aperture_m`）。
2. **三步标定与动力学 Sys-ID**：运行 APEX `forward_kinematics` 对账、桌面 ChArUco/AprilTag 多视角联合标定与 TCP 四角点触校验对齐双臂基座、桌面高程及 3 路相机外参；并通过悬空小幅激励 Sys-ID 拟合延迟与带宽复刻纯 Python 伺服步进层。
3. **夹爪与相机公共契约对齐**：跨端 `left/right_gripper_width` 统一定义为 `[0.0, 0.090] m`（直接对应 90C 导轨行程，`invert_stroke: true`），MuJoCo 通过软胶 `solref`/`solimp` 复现视触觉指垫压陷；全仓统一相机命名 `cam_high`、`cam_left_wrist`、`cam_right_wrist`，真机预计算 `cv2.remap` 一次完成去畸变、主点居中与 `320×240` 下采样以对齐 MuJoCo `fovy`。
4. **双基准任务迁移与真机闭环**：将 `stack` 与 `handover` 迁移至标定工作区并内建三层域随机化，打通 `hardware/tianji` ROS 2 后端与单手柄微分 IK 遥操源（同时预留现有“边拖边录 + 脚踏板”程序导入接口），随后按三层结构支持 `mujoco` 与 `tianji` 混合训练或真机微调。
