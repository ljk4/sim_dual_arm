# 重要实践与经验

保存值得长期复用的重要尝试、对比、故障定位和结果，积累项目的实践经验。
可以收录成功、失败或否定原假设的结果；重点是问题如何判断、证据支持什么，
以及以后在什么条件下可以复用。

## 收录规则

- 用户主动提出收录的内容，按其指定范围记录。
- 助手认为值得收录的内容，先说明收录理由、已有证据和可复用经验，取得用户
  同意后再建立正式条目。未获同意不自动收录，也不追溯批量整理已有尝试。
- 每篇注明收录依据与日期，关联对应阶段和实际产物；只记录必要的确认事项，
  不抄录完整聊天或工具流水。

可讨论的收录范围包括控制与通信问题、数据质量、模型对比、环境复现和工程设计
取舍。是否重要由具体问题和证据决定，不预先将某次尝试认定为可推广的经验。

## 组织与内容

一个重要问题或一组相关对比一份文档，命名为 `YYYY-MM-DD-<topic>.md`。同一问题
的后续尝试更新原文并注明日期，结论改变时保留原有证据和修订原因。

每篇建议包含：

1. 问题、背景、尝试目的和收录依据。
2. 环境与版本、数据、配置、随机种子和必要的复现条件。
3. 采用的方案、对照与关键操作。
4. 实际结果、失败现象和日志/指标/视频等证据位置。
5. 原因分析、可复用经验、适用条件与尚未确认的部分。
6. 复现入口、后续建议和相关阶段/功能链接。

实际观察与推断分别说明，单次结果注明样本和适用范围；缺失证据直接标明。
大体积日志、视频、数据和模型保留在原产物目录，这里引用路径与必要摘要，不复制。

[阶段历史](../history/README.md)保留原计划和完整实施事实，本目录提炼经确认的
实践经验；[功能说明](../features/README.md)描述系统当前能力。它们通过链接关联，
避免重复维护整份流水或将实验推断写成已实现行为。
