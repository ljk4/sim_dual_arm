# ACT 推理停滞、执行误停与首次堆叠成功的修复经验

收录日期：2026-11-03。收录依据：用户本次主动提出“总结此次修复发现的问题和修复方法，看看能否写入经验部分”，按此次修复范围整理。

相关阶段：[DSH-045](../history/dsh-045.md)～[DSH-051](../history/dsh-051.md)，最终验收集中在 [DSH-048](../history/dsh-048.md)。本篇提炼判断方法与适用边界，完整执行过程仍由阶段历史维护。

## 1. 结论与适用范围

“ACT 推理时机械臂几乎不动”不能直接归因于模型只会输出静止动作。本次发现，完整预测中有明显运动，但过短的执行窗口没有充分推进后续动作；恢复推进后，又依次暴露了预测切换、启动稳定和浮点边界判定问题。

在不追加训练的情况下，调整执行配方并修复实现缺陷后，同一 20K 模型完成了一次真实物理堆叠：任务耗时 **25.85 秒**，释放、退开后稳定支撑 **2 秒**。没有向 ACT 输入物体真值，也没有用示教、IK 或回放接管动作。

该结果来自**同场景修复回归**，只能说明组合方案在这一场景跑通。各项调整并非完整的单变量闭环实验，不能据此确定最优窗口、各项收益或泛化成功率。右腕视角仍存在目标遮挡，完整质量门禁尚未通过。

## 3. 发现的问题与修复方法

### 3.1 只看短执行窗口，会把推进不足误判成模型静止

原配方每次只选 2 点／100 ms。对 81 个匹配的在线预测检查后发现：完整 3 秒块的右臂最大位置变化量中位数约 **1.86 rad**，前 100 ms 约 **0.066 rad**。完整块并非全部停在当前状态附近。

在同一真实请求的离线计算中，2 点窗口产生的参考位移约 0.0039 rad，20 点约 0.3283 rad。增加窗口后，真实仿真中机械臂恢复了明显推进，随后才暴露其他拒绝原因。最终配方结合接续余量和参考偏差检查，采用 10 点／0.5 秒。

**可复用经验：**同时检查完整预测、被选中的时间窗口、插值后的参考和实测运动。模型预测长度、执行窗口、查询频率和控制周期必须分别记录。不要仅凭视频、单个首点或验证 loss 判断模型是否静止。

**证据边界：**离线比较复用了旧 anchor，没有重新推进物理；不能代替新闭环，也不能证明 0.5 秒在其他模型和任务中最优。详见 [DSH-045](../history/dsh-045.md) 和 [窗口对照](../../.build/reports/dsh-045/window-probe.json)。

### 3.2 新旧预测切换不连续，缩短窗口也未必解决

30401 第 8 次预测相对执行参考的关节偏差约 **0.229 rad**，超过当时的 0.15 rad 预算。同一失败请求缩到 2～25 点仍被拒绝，说明仅改窗口长度不足以解决预测切换问题。

修复在 policy 侧对已经通过准入的历史预测做时间融合。当前观测时刻为 `t`、历史观测为 `s`、周期为 `P=50 ms`，只融合同一未来时刻：

```text
t + (i + 1) * P = s + (j + 1) * P
weight = exp(coeff * (t - s) / P)
```

最终系数为 0.01，正系数给予较老预测更高权重。按未来时刻分别归一化；没有历史覆盖的尾部使用新预测。历史按会话隔离，reset 清空，只有成功保存和提交的有效预测进入历史。

**可复用经验：**异步查询的间隔可能超过一个动作周期，融合须按绝对执行时刻对齐，不能直接平均同一数组下标。保留历史观测身份和融合贡献数，防止平滑后无法解释动作来源。

详见 [DSH-047](../history/dsh-047.md)、[融合实现](../../components/learning/src/dual_arm_learning/act_temporal.py) 和 [同一失败请求的融合对照](../../.build/reports/dsh-045/ensemble-probe-30401.json)。该离线通过不单独证明物理成功。

### 3.3 reset 完成不等于任务可准备，也不等于适合立即推理

这里有两个不同问题，采用了不同处理：

- **任务准备竞态：**30400 在首次预测前收到 `TASK_NOT_QUIESCENT`。只对此明确响应进行有界重试，沿用同一请求身份；服务等待、调用和重试共用一个总墙钟期限，支持取消，其他错误不重试。后端静止阈值不变。
- **策略启动状态：**reset 后的 PD 收敛过程使状态偏离示教中的稳定待机分布。独立静置采样中，50 ms 观测的预测未通过初始参考检查，后续采样改善。最终增加可配置的 2 秒仿真稳定等待，再取新观测并开始任务计时；没有改测量值、模型或归一化统计。

**可复用经验：**把接口准备条件和策略输入稳定条件分开。优先根据明确反馈重试；必须等待时，说明用仿真钟还是墙钟、是否占任务预算、如何取新帧和响应取消。不要用无限重试隐藏故障。

2 秒是本场景验证过的配方，不是普适常数，也未证明是最短必要时间。详见 [DSH-046](../history/dsh-046.md)、[DSH-049](../history/dsh-049.md) 和 [静置采样数学检查](../../.build/reports/dsh-048/rest-math.json)。

### 3.4 策略目标与执行参考的偏差预算，需要单独识别和决策

平滑参考受速度和加速度约束，可能暂时到不了策略目标。原关节 0.15 rad／夹爪 0.02 m 的参考偏差预算多次触发拒绝；例如 30403 夹爪偏差约 0.0285 m。经用户明确批准，独立仿真实验改为 **0.30 rad／0.04 m**。

这是一项实际工程取舍，不是浮点修复。机器人硬位置范围、速度／加速度限制、实测跟踪检查、ACK 和成功判定没有随之放宽。

**可复用经验：**看到“超差”先确认比较的是哪两个量。预测准入、目标与参考偏差、参考与实测误差具有不同含义，不能用同一个“大容差”处理。此次参数仍属于仿真实验配方，不直接迁移到真机。决定与证据见 [DSH-048](../history/dsh-048.md)。

### 3.5 合法值的加权平均，也可能越界一个浮点舍入量

30402 的原始预测已通过夹爪准入，融合结果却得到 **0.08000000000000002 m**，超过严格上限 0.08 m，导致整块拒绝。

修复将每个时刻、每个轴的融合结果约束在**实际参与融合值的最小值与最大值之间**，恢复加权平均应有的凸组合范围；增加常量边界的长序列回归测试。没有放宽机器人限位，也没有新增机械臂目标投影。

**可复用经验：**输入校验通过不代表计算结果自动保留输入的不变量。浮点修正应有数学依据和明确范围，不应靠通用裁剪掩盖非法输入。实现与验收见 [DSH-047](../history/dsh-047.md) 和 [融合测试](../../tests/unit/test_act_temporal.py)。

### 3.6 Ruckig 的极小制动前缀被导出器当成真实额外制动

30502 夹住方块后发生 `INVALID_RUCKIG_EXPORT`。从真实 MCAP 重建 16 维请求发现，起始夹爪速度为 **0.04000000000000001 m/s**，与 0.04 m/s 上限仅有舍入差。Ruckig 因此产生约 **2.20×10⁻¹⁴ 秒**的制动前缀；旧导出器拒绝所有非零前缀。

修复只折叠在现有时间量化下为 **0 ns**、结构合法、状态变化及与主段衔接均满足既有边界容差的前缀。保留原始 anchor 的位置和速度，不额外添加 1 ns，不裁剪 Ruckig 输入速度。可表示的非零制动段、非法结构、非有限值或大状态跳变仍拒绝。

**可复用经验：**在连续时间算法与离散时间协议之间，检查量化及边界状态。不能因持续时间很短就直接丢弃，也不能把全部非零值都当成有意义的物理事件。本修复没有实现通用制动前缀支持。

证据：[修复前真实请求](../../.build/reports/dsh-048/brake-probe.json)、[修复后重建](../../.build/reports/dsh-050/brake-probe-fixed.json)、[DSH-050](../history/dsh-050.md)；实现见 [ruckig_export.py](../../components/backend_sim/src/robot_backend_sim/ruckig_export.py)。

### 3.7 静止速度的定义不一致，使正常夹持被判为跟踪超时

原 30600 最后显示 `STREAM_ANCHOR_UNAVAILABLE`，但后端更早已发生 `TRACKING_TIMEOUT`。接触记录显示：右夹爪约 4 cm，双指接触同一源块、各约 1 N，指速低；闭合目标为 0 时，物体自然阻挡夹爪继续闭合。

真正触发误判的是参考速度 **+5.339×10⁻¹⁴ m/s**：闭合接触判定采用严格 `<=0`，卸载逻辑却把 `<=1e-9 m/s` 视为未打开，造成两个分支都不接纳这一数值静止状态，超差累计到 2 秒。

修复提取并共享已有的 **`REFERENCE_VELOCITY_ATOL_M_S=1e-9`**。闭合接触分类沿用相同零速度定义；真实张开仍遵守原有有界卸载规则。没有提高接触力、指速、实测跟踪或超时阈值。

**可复用经验：**先追溯最早的失败事件，再解释上层后果；不要在运动已失败后盲目重试获取 anchor。相邻状态机对“零”“打开”“关闭”的数值定义应一致，并带明确单位。

证据：[接触与跟踪重建](../../.build/reports/dsh-048/tracking-probe.json)、[DSH-051](../history/dsh-051.md)；实现见 [contact_unload.py](../../components/backend_sim/src/robot_backend_sim/contact_unload.py) 和 [motion.py](../../components/backend_sim/src/robot_backend_sim/motion.py)。修复后的同场景回归完成堆叠，但不能将全部组合收益都归因于这一项。

## 4. 后续遇到类似问题的排查顺序

1. 固定模型、processor、profile、有效配置和运行身份，核对实际挂载的源码；保留失败原件。
2. 按时间找最早失败：模型调用前、动作准入、参考规划、接续、实测跟踪，还是物理任务本身。
3. 对齐同一观测和绝对时刻，比较完整预测、选中窗口、准入值、融合目标、执行参考和实测反馈。
4. 用保存的真实请求做最小重建，区分模型输出、预算拒绝、浮点计算和状态分类问题。
5. 先做有针对性的回归，再通过公共入口运行物理闭环；记录未通过项，不以离线检查替代闭环。
6. 同场景修复回归和新种子泛化评估分别建账。进程退出、动作执行、物理成功、录制完整和图像质量分别报告。

以上六层动作值必须分别保留。当前产物中 `raw_act` 为原预测，`admitted` 为准入目标，`execution_targets` 为融合后的传输目标；`correction=admitted-raw_act`，不包含融合变化。参考和实测反馈另存于 MCAP。

不同阈值也要分别记录：原预测夹爪准入修正上限为 0.03 m；策略目标相对参考的允许偏差为关节 0.30 rad／夹爪 0.04 m；`1e-9 m/s` 是零速度分类的数值容差。这些数值不能互相代用。
