## 读取与目标

读取 progress、`deliveries/phase-09.md`、真实 `panda_stack/binding.yaml` 及相关选择入口。交付一个可照着新增方案的模板，证明配方选择确实影响输入。

## 模板

完善 `shared/scenarios/_template/README.md` 与 `binding.example.yaml`。README 说明目录结构、路径基准、模型引用、校验及 prepare 命令；引用已有权威档案的例子与实际解析行为一致。示例使用明显占位值，未填写时不能启动 Panda。

明确区分方案、实现与 checkpoint：更换兼容 checkpoint 使用模型引用；需要保留两组配方时，在同一方案中显式命名，不建立配置继承体系。

| 更换内容 | 主要修改位置 | 实现边界 |
| --- | --- | --- |
| checkpoint | bundle 引用或命令行覆盖 | learning 验证模型、处理器及输入输出档案 |
| 学习算法 | learning 选择与数据/训练/服务配方 | 新适配在 learning 实现 |
| 机器人 | profiles、控制/场景配方与执行映射 | 驱动和运动映射由对应端提供 |
| 仿真后端 | backend 选择、场景配方与部署要求 | 新后端在 simulation 实现 |
| 任务 | task_type、示教/评价配方与必要扩展 | 任务逻辑归所属端，专用接口归方案 |
| 仿真切真机 | hardware 实现、设备配置与可用能力 | 当前仓库没有已验证的真实驱动 |
| 新观测/动作能力 | 公共接口与对应生产/消费端 | 按实际能力需求演进协议 |

支持某实现后才能在 binding 中选择它。用模板说明这一点，不预建算法、机器人、驱动或后端占位实现。

## 替换验证

在临时目录构造一个标为 test_only 的方案，显式选择另一份有效 recipe。用现有解析与一个实际 prepare 入口证明 recipe 的不同数值进入生成配置，公共生产代码无需增加方案名分支。

复用已有 cwd、缺模型、参数互斥和依赖边界测试。只补齐尚无覆盖的模板或替换行为，不重复测试阶段 02～05 的已知结果。

核对公共生产包的依赖边界。Fake Policy 若依赖 learner 类型，保持学习端专用归属；当前验证不需要另建协议替身。发现真实反向依赖时直接调整其归属或调用，不新建全仓依赖审计平台。

## 交付

模板中的命令对应真实入口；交接记录替换测试实际改变的输入与输出。该结果证明配置可替换，不代表第二个机器人或后端已经实现。

更新 progress，写 `deliveries/phase-10.md`；已知问题集中记录。完成后停止。
