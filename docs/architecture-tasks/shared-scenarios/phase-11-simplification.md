## 优先处理的调用链

| 范围 | 重点 |
| --- | --- |
| `robot_contracts/binding.py`、各端 scenario 选择模块 | 同一入口内重复解析 binding/档案、重复找根目录和拼接同义来源记录 |
| runtime 的 record_preflight、record_workers、record_pool | 预检、配置准备与启动之间重复的文件读取和身份计算；同一进程可直接传递已解析结果 |

这些是查找入口，不要求每处都改。跨宿主/容器、独立 worker 或延迟启动属于真实执行边界，不能拿进程内结果复用代替必要的边界检查。

## 精简方式

1. 沿一个真实入口找调用者和写入/读取位置，直接删去无作用的分支、记录或包装。相同职责的重复逻辑优先合并到已有模块，端私有逻辑留在端内。
2. 同一命令已经解析过的 binding、recipe、档案或包信息，向下传递结果；不为此建立持久缓存、缓存失效协议或共享状态管理器。
3. 新增的无人消费摘要、只写日志的证明链和重复哈希可删除。既有 Profile/模型/轨迹协议摘要及 SDK 重建判断保留其真实作用，不改变旧产物。worker 当前使用的身份校验，只有在用更直接方式保持同一方案和配置约束时才替换。
4. 单层 DTO 足以表达的数据不再套一层等价模型；简单函数足以表达的调用不引入基类、插件注册器或通用校验框架。保留有实际职责的端适配层。
5. 内部未使用 API 和新增冗余字段可以连同调用者一起清理。受支持 CLI、真实旧记录与已存在的产物消费者仍需正常工作；不为不存在的调用者保留兼容包装。
6. 测试保留可观察行为和真实故障边界，合并重复构造与重复断言。代码规模遵守现有规范，不设删行比例，不为达到数字拆模块或删必要校验。

## 保持的行为与验证

方案选择仍决定实际 recipe 和 bundle；不支持的实现明确失败；learning 继续验证真实模型；错误模型来源在输出前拒绝；核心 SDK 不能冒充完整包集；预检失败不预留正式预算或启动 backend。公共代码的端依赖边界与物理参数保持不变。

每完成一组精简，运行对应现有测试；同一段代码无需反复跑同一组。改到生成接口才重建 SDK，改到真实进程编排才补一次相关有界运行。整体闭环集中在阶段 12。

更新 progress，写 `deliveries/phase-11.md`：说明实际删除/合并了什么、保留了哪些有作用的边界及相关测试结果。无需逐文件摘要、复杂度评分或大规模前后统计。完成后停止。
