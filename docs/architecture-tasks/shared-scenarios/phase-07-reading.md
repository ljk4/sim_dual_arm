# 阶段 07 收尾：历史反馈读取

状态：完成（2026-11-11）。结果与已知问题见 [阶段 07 交接](deliveries/phase-07.md)。

## 当前行为与目标

读取 progress、`deliveries/phase-07.md`，并查看 runtime 的 `offline/export_episode.py`、`mcap_reader.py` 和 `legacy_feedback.py`。

普通导出的 `_read_metadata` 仍会把旧反馈交给当前生成类型反序列化；legacy 读取器仅根据两条固定数组声明识别布局。仓库有真实旧 MCAP，因此这些读取路径需要明确区分已知格式。

目标是让导出与审计在解码前选择正确类型或明确拒绝，让专用旧读取器只接受它实际能够解析的完整布局。

## 实现

- 复用一处简短的定义识别逻辑，覆盖实际反序列化反馈的导出和审计入口。普通入口遇到旧格式可以指向现有 legacy 命令，不能尝试用当前类型读取。
- legacy 识别与真实旧 MCAP 中的完整消息定义比较，包含字段类型、顺序、数组边界及所用嵌套消息。可统一注释和空白后直接比较，不新增指纹库、动态类型系统或迁移框架。
- 保留当前 DTO 对解码后数值与关系的校验。定义识别与 DTO 校验各负责一层，不互相替代。
- 读取异常时释放本次 reader；拒绝发生在解码和业务输出之前。

## 验证与交付

复用现有测试，补齐旧导出入口在调用当前反馈解码器之前拒绝、当前格式正常读取、包含两个旧数组声明但缺失完整布局时拒绝这三类行为。用一个字段类型或顺序变化证明完整定义比较有效，不扩展畸形输入矩阵。

复用阶段 07 已选真实样本，确认旧读取器得到相同关节与夹爪值；不重读全仓 MCAP。完整旧 episode 的导出/审计在阶段 12 验证。
