# 阶段 08：轨迹表示与求解器来源分离

状态：待实施。遵守 [总要求](README.md) 与仓库 RULES。

## 读取与目标

读取 progress、`deliveries/phase-07.md` 及 [历史读取收尾](phase-07-reading.md) 的结果。阶段 07 的旧类型读取入口修好后，再修改轨迹接口。

公共消费者应根据已支持的曲线表示、时间和数值接受轨迹，而非要求生产者使用 Ruckig 0.15.3。当前 simulation 继续使用原求解器，控制结果保持原语义。

沿实际调用链读取 contracts 的 follower/reference DTO、`robot_trajectory`、`FollowerReference.msg`、ROS 转换器、simulation 生产端及 runtime 导出/审计。先定位版本判断与 `ruckig_duration_ns` 的用途，再修改这些位置。

## 实现

1. 将曲线表示、采样和归一化约定与生产者算法/版本分开。公共数值校验只依赖前者；生产者信息保留真实值，复用现有记录位置，不建立算法注册表。
2. 为 `ruckig_duration_ns` 选择一个含义准确的通用字段，保持其与计划时长、最终段、采样网格的原有关系。同步 DTO、IDL、转换、生产者与消费者；仅在确有不兼容处调整版本。
3. 保留现有轨迹摘要的协议作用与数值检查，不新增来源指纹、额外摘要层或逐次审计文件。求解器调用与专用版本约束留在 simulation。
4. 保留关节数、段数、3 秒 horizon 等现有边界。此阶段不做参数体系扩展，不实现第二个求解器。
5. 为已有历史记录选定明确读取办法，复用阶段 07 的入口校验。只处理现有旧格式；不把当前 SDK 用于不匹配的 CDR，也不新增通用迁移框架。

## 验证与交付

复用轨迹、follower 和审计测试，验证两项仍需证明的行为：同种合法曲线可携带不同生产者信息；当前 Ruckig 曲线的时长、采样和控制含义保持一致。对未知表示与真实支持输入中的非法时间/系数，保留现有拒绝行为。

IDL 或转换变化时，正常重建受影响 SDK，检查一次生成类型往返与受影响消费者。未修改的 Policy SDK 不重建。历史样本完成本阶段涉及字段的读取；完整 episode 留阶段 12。

更新 progress，交付 `deliveries/phase-08.md`，说明最终字段含义、必要版本变化、历史读取入口及验证结果。已知问题集中记录。完成后停止。
